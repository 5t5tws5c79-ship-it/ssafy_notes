# Python 객체지향 프로그래밍 정리 (OOP) — 1편

## 1. 프로그래밍 패러다임 — 절차지향 vs 객체지향

### 절차지향(Procedural)이란?

**함수와 로직 중심**으로 작성하며, 데이터를 **순차적으로 처리**한다. **위에서 아래로 실행**되는 방식.

- 절차지향적 사고: **입력을 받고 → 처리하고 → 결과를 내는** 과정이 위에서 아래로 **순차적으로 흐르는 형태.**
- **순차적 명령어 실행**이 핵심.
- 데이터를 **다시 재사용**하기보다는, **처음부터 끝까지 실행되는 결과물**이 중요하다.

### 절차지향의 한계

| 한계 | 설명 |
|------|------|
| **복잡성 증가** | 규모가 커지면 데이터와 함수의 관리가 어려워짐 |
| **전역 변수 증가** | 여러 함수가 전역 변수를 공유하며 관리가 어려워짐 |
| **유지보수 문제** | 코드 수정 시 **영향 범위 파악**이 어려움 |

## 2. 객체지향 프로그래밍(OOP)이란?

> **클래스는 설계도, 인스턴스는 실제 물건.**

### 객체지향 사고 예시

사람(객체) 안에 `name`, `age`와 이와 관련된 기능(메서드)을 **함께 포함**시킨다.

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def introduce(self):
        print(f'안녕하세요, {self.name}입니다. 나이는 {self.age}살입니다.')


alice = Person('Alice', 25)
alice.introduce()   # 객체가 자신의 정보를 출력
```

> **데이터**와 **그 데이터를 처리하는 함수(메서드)**를 **하나의 단위로 묶어서** 조직적으로 관리하는 것 — 이것이 객체지향의 핵심이다.

### 절차지향 vs 객체지향 비교

| | **절차지향** | **객체지향** |
|---|---|---|
| 구조 | **함수와 데이터가 분리**됨 | **데이터와 그 데이터를 처리하는 메서드를 하나의 객체**로 묶음 |
| 중요한 것 | 함수의 **호출 순서** | 객체 간 **상호작용과 메시지 전달** |
| 질문의 초점 | "**어떤 순서**로 처리할까?" | "**어떤 객체**가 이 문제를 해결할까? 이 객체는 **어떤 속성**을 가지나?" |
| 데이터의 역할 | **수동적** 존재 (함수가 데이터를 처리) | **능동적** 존재 (객체가 스스로 기능을 수행) |

> **절차지향 vs 객체지향은 "좋고 나쁨"의 문제가 아니다.** 객체지향은 절차지향 위에 **"객체"라는 개념을 도입**해서, **상속·코드 재사용성·유지보수성** 등의 이점을 얻는 패러다임이다.

## 3. 객체와 클래스

### 객체 (Object)

**실제 존재하는 사물을 추상화한 것.** **속성**과 **동작**을 가진다.

> `str`, `int`, `list` 같은 파이썬 기본 자료형도 사실은 **원시 클래스의 인스턴스**다. 파이썬에서는 **"모든 것이 객체"**다.

### 클래스 (Class)

**블루프린트(설계도).** 속성과 메서드를 하나의 묶음으로 정의한다.

- **클래스** → 속성과 메서드를 정의하는 **설계도**
- **인스턴스** → 그 설계도로 실제로 **만들어진 개별 물건**

### 클래스 기본 문법

```python
class MyClass:
    ...
```

> 클래스 이름은 **파스칼 케이스(PascalCase)**로 작성하는 것을 권장한다. (`MyClass`, `Person`, `Circle`처럼 단어 첫 글자를 모두 대문자로) 호출할 때 함수와 비슷하게 생겨서, 함수와 클래스를 구분하기 위한 관례이기도 하다.

## 4. 매직 메서드 (Magic Method)

`__init__`은 **생성자(constructor) 메서드**로 불리며, **새로운 객체를 만들 때 필요한 초기값을 설정**한다.

- 이름 양옆의 `__`(더블 언더스코어)는 **파이썬이 자동으로 인식하는 특수 토큰**이다. 개발자가 직접 호출 시점을 정하는 게 아니라, **파이썬이 알아서 관리**한다. (객체 생성 시 자동 호출됨)

## 5. 인스턴스 (Instance)

### 정의

**클래스를 통해 생성된 객체.** 설계도로 실제로 만든 **개별 물건.**

### 객체 vs 인스턴스 — 뭐가 다른가?

아이유는 "객체"이다 → O (아이유는 실재하는 사물)
아이유는 "인스턴스"다 → X (소속을 밝히지 않았음)
아이유는 "가수의 인스턴스"이다 → O (소속이 명확함)

> **핵심 차이:** "객체"는 그 자체로 성립하는 말이지만, **"인스턴스"는 반드시 "무엇의" 인스턴스인지 소속을 말해줘야 한다.**

```python
'hello'   # 이건 str 클래스의 인스턴스다 → 맞는 말
```

### 클래스의 인스턴스 타입 확인

```python
class Singer:
    pass

iu = Singer()
print(type(iu))     # <class '__main__.Singer'>
```

> **인스턴스는 자신이 소속된 클래스가 무엇인지 말해줘야 한다.** 하나의 객체는 항상 **특정 클래스의 인스턴스**다.

> **💡 궁금증 — `__main__`은 뭘 의미하나요?**
> 파이썬은 실행되는 모든 `.py` 파일을 하나의 **모듈**로 취급하고, 각 모듈은 `__name__`이라는 내장 변수를 가진다.
> - 어떤 파일을 **직접 실행**하면(`python my_file.py`), 그 파일의 `__name__`은 자동으로 `'__main__'`이 된다.
> - 반대로 그 파일이 **다른 파일에서 import되어 쓰이면**, `__name__`은 `'__main__'`이 아니라 **그 파일의 실제 모듈 이름**(예: `'my_file'`)이 된다.
>
> 즉, `<class '__main__.Singer'>`는 "이 `Singer` 클래스는 **현재 직접 실행 중인 파일** 안에서 정의되었다"는 뜻이다. `if __name__ == '__main__':`이라는 익숙한 관용구도 같은 원리다 — "이 파일이 (import된 게 아니라) **직접 실행되고 있을 때만** 이 코드를 실행하라"는 조건문이다. 나중에 여러 파일로 프로젝트를 나눌 때 아주 중요해지는 개념이니 기억해두면 좋다.

## 6. 클래스의 구성요소

### 6-1. 생성자 메서드 (`__init__`)

인스턴스 **생성 시 자동 호출**되는 매직 메서드. `__init__`이라는 이름으로 정의하며, **인스턴스 변수의 초기화**를 담당한다.

### 6-2. 인스턴스 변수 (속성, Instance Variable)

각 인스턴스가 가지는 **고유한 속성.** `self.변수명` 형태로 정의하며, **인스턴스마다 독립적인 값**을 유지한다.

### 6-3. 클래스 변수 (Class Variable)

클래스 내부에서 **직접 정의**하며, **모든 인스턴스가 공유**하는 속성.

```python
class Circle:
    pi = 3.14              # 클래스 변수 — 모든 인스턴스가 공유

    def __init__(self, radius):
        self.radius = radius   # 인스턴스 변수 — 인스턴스마다 다름


c1 = Circle(1)
c2 = Circle(2)

print(c1.radius)   # 1
print(c2.radius)   # 2

print(c1.pi)        # 3.14
print(c2.pi)        # 3.14  (같은 클래스 변수를 공유)
print(Circle.pi)    # 3.14  (클래스 이름으로 직접 접근도 가능)
```

### ⚠️ 클래스 변수에 인스턴스를 통해 값을 대입하면?

```python
c1.pi = 100
print(c1.pi)   # 100    ← c1만의 새로운 "인스턴스 변수"가 생김
print(c2.pi)   # 3.14   ← 클래스 변수는 그대로!
```

> **핵심 원리:** `c1.pi = 100`은 클래스 변수 `pi`를 **수정하는 게 아니라**, `c1`에 **새로운 인스턴스 변수 `pi`를 만들어버리는 것**이다. 그 이후 `c1.pi`를 조회하면 **클래스 변수보다 먼저 인스턴스 변수를 찾아서** `100`을 보여준다. `c2`는 영향을 받지 않았으므로 여전히 클래스 변수 `3.14`를 그대로 참조한다.
> 클래스 변수 자체를 진짜로 바꾸고 싶다면 `Circle.pi = 100`처럼 **클래스 이름으로 직접 접근**해야 한다.

## 7. 메서드 (Method)

객체가 **어떻게 동작할지**를 정의한다. 크게 세 종류가 있다: **인스턴스 메서드, 클래스 메서드, 스태틱 메서드.**

### 7-1. 인스턴스 메서드 (Instance Method)

**인스턴스의 상태를 조작하거나 동작을 수행**하는 메서드.

- **인스턴스마다 독립적으로 행동**할 수 있게 만드는 것이 인스턴스 메서드의 역할.
- 클래스 내부에 **함수처럼 생겼다.**
- **첫 번째 인자로 반드시 인스턴스 자기 자신(`self`)을 받는다.**
  - `self`는 **매개변수 이름일 뿐**이라 다른 이름으로 바꿔도 문법적으로는 작동하지만, **다른 이름을 쓰지 않을 것을 강력히 권장**한다. (관례를 깨면 다른 개발자와의 소통에 혼란을 줌)

### `self`의 동작 원리

```python
'hello'.upper()
```

이렇게 쓰지만, 실제 파이썬 내부에서는 다음과 같이 동작한다:

```python
str.upper('hello')
```

- **`str` 클래스가 `upper` 메서드를 호출**했고, 그 **첫 번째 인자로 문자열 인스턴스(`'hello'`)가 들어간 것.**
- 즉, `'hello'.upper()`라는 **단축형 호출**은 파이썬이 편의를 위해 지원해주는 문법이고, 실제로는 **클래스의 메서드에 인스턴스 자신을 첫 인자로 넘겨서 호출**하는 것이다.

> **인스턴스 메서드의 첫 번째 인자가 반드시 인스턴스 자기 자신인 이유:**
> 메서드는 **인스턴스의 상태를 조작**하기 위한 것이기 때문에, 메서드 안에서 **`self`(자기 자신)에 접근할 수 있어야** 한다. 그러려면 **첫 번째 인자로 `self`를 받아야만** 한다 — 이게 없으면 메서드 안에서 "내가 지금 어떤 인스턴스인지" 알 방법이 없어 `self`를 컨트롤할 수 없다.
>
> 객체가 **스스로 자신의 메서드를 호출**해서 동작하는 것 — 이것이 파이썬이 지원하는 **객체지향적인 표현 방식**이다.

> **💡 궁금증 — 파이썬만 이런 식으로 `self`를 명시하나요? 원래 OOP를 염두에 두고 설계된 언어가 아닌가요?**
> 좋은 질문이야. 두 가지로 나눠 답할 수 있어.
>
> **1) 파이썬은 처음부터 객체지향을 염두에 뒀다.** 파이썬은 1991년 귀도 반 로섬이 만들 때부터 클래스와 객체 개념을 지원한 **멀티패러다임 언어**였고, "모든 것이 객체"라는 철학이 초기부터 깔려 있었다. OOP를 나중에 억지로 끼워 넣은 언어가 아니다.
>
> **2) `self`를 명시적으로 쓰는 건 파이썬의 의도적인 설계 철학이다.** Java, C++, JavaScript 같은 언어들은 `this`(또는 `self`에 해당하는 것)를 메서드의 **매개변수 목록에 안 적어도** 암묵적으로 쓸 수 있게 되어 있다. 반면 파이썬은 **"명시적인 것이 암묵적인 것보다 낫다(Explicit is better than implicit)"**는 설계 철학(Zen of Python)을 따라서, "이 메서드가 어떤 인스턴스에 속해 동작하는지"를 **매개변수로 눈에 보이게 드러낸다.** 그래서 파이썬에서는 인스턴스 메서드를 쓸 때 **무조건 `self`를 첫 매개변수로 명시**하고 시작해야 하는 것이다.

### 생성자 메서드도 인스턴스 메서드의 일종

**생성자 메서드(`__init__`)** 역시 큰 카테고리로 보면 **인스턴스 메서드**다. 인스턴스 변수들의 **초기값을 설정**하는 역할을 한다.

### 생성자 메서드 활용 — 상세 정리

```python
class Person:
    def __init__(self, name):
        # 왼쪽 name : 인스턴스 변수 name (self.name)
        # 오른쪽 name : 생성자 메서드의 매개변수 이름
        self.name = name
        print('인스턴스가 생성되었습니다.')

    def greeting(self):
        print(f'안녕하세요 {self.name}입니다.')


person1 = Person('지민')   # 인스턴스가 생성되었습니다.
person1.greeting()          # 안녕하세요 지민입니다.
# Person.greeting(person1)  ← 위와 완전히 동일한 호출 (내부 동작 그대로)
```

**`self.name = name` 한 줄을 왼쪽/오른쪽으로 나눠서 정확히 이해하기:**

| 위치 | 정체 | 설명 |
|------|------|------|
| **왼쪽** `self.name` | **인스턴스 변수** `name` | 이 인스턴스에 **저장될(고정될) 값**. 앞으로 `person1.name`으로 접근하게 될 그 값 |
| **오른쪽** `name` | **매개변수** `name` | `Person('지민')`처럼 호출할 때 **임시로 전달받은 값**. 함수가 끝나면 사라지는 지역 변수 |

> **왜 이름이 똑같은데 헷갈리지 않나?** `self.name`(왼쪽)과 `name`(오른쪽)은 **점(`.`)의 유무로 완전히 다른 대상**이기 때문이다. `self.name`은 "self라는 객체에 속한 name 속성"이고, `name`은 "지금 이 함수 안에서만 존재하는 매개변수"다. `self.name = name`은 **"매개변수로 받은 임시값(오른쪽)을, 인스턴스에 영구적으로 저장될 속성(왼쪽)에 대입해라"**는 뜻이다. 이렇게 저장해두어야 `greeting()` 같은 **다른 메서드에서도 `self.name`으로 그 값을 다시 꺼내 쓸 수 있다.**
>
> 같은 이름을 쓰는 게 관례이긴 하지만, `self.name = n`처럼 **매개변수 이름을 다르게 써도 동작은 똑같다.** 다만 관례를 따르는 게 가독성 면에서 훨씬 좋다.

**마지막 줄의 의미:**

```python
person1.greeting()          # 단축형 호출 (일반적으로 쓰는 방식)
Person.greeting(person1)    # 실제 내부 동작 (클래스.메서드(인스턴스) 형태)
```

두 줄은 **완전히 동일한 호출**이다. `person1.greeting()`이라는 편리한 문법 뒤에는, 사실 `Person` 클래스의 `greeting` 메서드에 **`person1`이라는 인스턴스를 첫 번째 인자(`self`)로 넘겨서 호출**하는 동작이 숨어 있다.

### 7-2. 클래스 메서드 (Class Method)

**클래스가 쓰는 메서드.** 클래스 변수를 조작하거나 클래스 레벨의 동작을 수행한다.

`@classmethod` **데코레이터**를 사용해서 클래스 레벨의 동작이 가능하도록 만든다.

```python
class Person:
    population = 0

    def __init__(self, name):
        self.name = name
        Person.increase_population()

    @classmethod
    def increase_population(cls):
        cls.population += 1


person1 = Person('Alice')
person2 = Person('Bella')

print(Person.population)   # 2
```

- 호출 시 **첫 번째 인자로 메서드를 호출한 클래스(`cls`)가 자동 전달**된다.
- **클래스를 인자로 받아** 클래스 속성을 변경하거나 읽는 데 사용한다.
- `cls`는 `self`와 마찬가지로 **매개변수의 이름일 뿐**이라 다른 이름으로 설정할 수 있지만, **다른 이름을 쓰지 않을 것을 강력히 권장**한다.

> **💡 궁금증 — 왜 `__init__`에서 `population += 1`로 직접 접근하지 않고, 굳이 클래스 메서드를 거쳐서 늘리나요?**
> `self.population += 1`처럼 인스턴스에서 직접 클래스 변수를 건드리면, 앞서 배운 함정(**"인스턴스 변수가 새로 생겨버리는 문제"**)에 걸릴 위험이 있다. 그리고 더 근본적으로는 **설계(디자인) 관점의 문제**다: "인구수를 늘리는 로직"은 **클래스 전체에 대한 책임**이지, 개별 인스턴스가 알아서 처리할 일이 아니다. 그래서 "클래스 레벨의 동작"은 **클래스 메서드로 명확히 캡슐화**해서, `Person.increase_population()`처럼 **의도가 드러나는 이름으로 호출**하는 것이 더 좋은 설계로 여겨진다. 단순히 "동작하냐 안 하냐"가 아니라 **"책임이 누구에게 있는가"**를 코드 구조로 표현하는 것이다.

### 7-3. 스태틱 메서드 (Static Method)

**클래스나 인스턴스와 상관없이 독립적으로 동작하는 메서드.**

- 클래스나 인스턴스의 **상태와 무관**하게, 예를 들어 **매개변수로 받은 값만으로** 결과를 낼 수 있는 **독립적인 동작**일 때 사용한다.
- `@staticmethod` 데코레이터를 사용하면, 클래스 내부에 있지만 **어떤 객체와도 관계없이 동작하는 메서드**를 만들 수 있다.

```python
class MathUtils:
    @staticmethod
    def add(x, y):
        return x + y


print(MathUtils.add(3, 5))   # 8   (self도 cls도 필요 없음)
```

> `self`나 `cls`를 받지 않는다는 게 핵심. 그냥 클래스라는 "네임스페이스(이름 공간)" 안에 관련 있는 함수를 넣어둔 것뿐이다.

## 9. 메서드 종류별 사용처 정리

| 메서드 종류 | 첫 인자 | 사용 상황 |
|-------------|---------|-----------|
| **인스턴스 메서드** | `self` | **인스턴스의 상태**를 조작할 때 |
| **클래스 메서드** | `cls` | **클래스 전체(공유 상태)**를 조작할 때 |
| **스태틱 메서드** | (없음) | 클래스·인스턴스 상태와 **무관한 독립적인 동작**일 때 |

### 실전 규칙 — 누가 무엇을 호출해야 하나?

- **인스턴스가 사용해야 할 것** → **인스턴스 메서드**
- **클래스가 사용해야 할 것** → **클래스 메서드, 스태틱 메서드**

> 사실 파이썬에서는 **클래스가 모든 메서드를(인스턴스 메서드까지도) 기술적으로는 호출할 수 있다.** 하지만 **클래스는 클래스 메서드와 스태틱 메서드만 사용해야 한다**는 게 원칙이다.
> 마찬가지로 **인스턴스도 모든 메서드를 호출할 수 있다.** 하지만 **인스턴스는 인스턴스 메서드만 사용해야 한다.**

### "Can"과 "Should"를 구분하라

- **클래스 입장:** 클래스 메서드와 정적 메서드를 호출하는 것이 **주된 역할.**
- **인스턴스 입장:** 본인(자기 자신)을 조작하는 것만 호출하는 게 **논리적으로 맞다.**
- 각 데코레이터를 만들어둘 때는 **설계 의도**가 이미 있었다. 기술적으로는(can) 다르게 호출하는 게 가능하지만, **논리적으로는(should) 회피해야 하는 패턴**이다.

> **💡 궁금증 — 자바에서는 이게 막혀 있지 않았나요?**
> 정확한 기억이야. **자바는 인스턴스 메서드를 클래스 이름으로 직접 호출하는 게 애초에 문법적으로 불가능**하다(컴파일 에러). 자바의 `static` 메서드는 인스턴스에서도 호출은 되지만(컴파일러가 경고를 주는 정도), 인스턴스 메서드를 클래스에서 호출하는 길 자체가 막혀 있다.
> 반면 **파이썬은 이런 규칙을 문법으로 강제하지 않고, "관례(convention)"로 지킨다.** `Person.greeting(person1)`처럼 인스턴스 메서드를 클래스에서 호출하는 것도 **문법적으로는 허용**된다. 이게 파이썬의 일반적인 철학이기도 하다 — **"우리는 모두 성인이다(we're all consenting adults here)"**라는 말처럼, 언어가 강제로 막기보다는 **개발자의 판단과 관례에 맡기는 경우가 많다.** 그래서 "can(기술적으로 가능)"과 "should(설계상 바람직함)"를 구분해서 이해하는 게 특히 파이썬에서는 중요하다.

## 10. (참고) 클래스와 인스턴스 간의 이름 공간 (Namespace)

- **클래스를 정의**하면, 클래스와 해당하는 **이름 공간(namespace)**이 생성된다.
- **인스턴스를 만들면**, 인스턴스 객체가 생성되고 **독립적인 이름 공간**이 함께 생성된다.
- 인스턴스에서 특정 속성에 접근하면, **인스턴스 → 클래스 순으로 탐색**한다.

> **TIP**
> - 같은 클래스로 만든 인스턴스라도 **서로 다른 이름 공간**을 가지므로, 인스턴스 간 변수 값이 서로 영향을 주고받지 않는다.
> - 속성 접근 시에는 **인스턴스 → 클래스 순으로 탐색**되니, **같은 이름의 속성이 중복될 경우 인스턴스 값이 우선**된다.

> 이건 앞서 봤던 `c1.pi = 100` 예시와 정확히 같은 원리다. `c1.pi`를 조회하면 파이썬은 먼저 `c1`이라는 **인스턴스의 이름 공간**을 뒤지고, 거기 없으면 `Circle`이라는 **클래스의 이름 공간**을 뒤진다. `c1.pi = 100`으로 `c1`의 이름 공간에 `pi`가 새로 생겼으니, 그다음부터 `c1.pi`는 인스턴스 값(100)을 먼저 찾아서 그걸 반환하는 것이다.

> **왜 이렇게 나누나?** 클래스와 인스턴스를 **모듈화**해서 각 객체가 **독립적으로 동작**하도록 보장하기 위함이다. 이는 **가독성·유지보수성·재사용성**을 높이는 데 도움을 준다.

## 11. 매직 메서드 (Magic Method) — 추가 정리

**던더 메서드(dunder method)**라고도 불린다. (Double UNDERscore의 줄임말) **특정 상황에서 자동으로 호출**된다.

### `__str__(self)`

내장 함수 `print()`에 의해 호출되어, **객체를 출력할 때의 문자열 표현을 변경**한다.

```python
class Person:
    def __init__(self, name):
        self.name = name

    def __str__(self):
        return f'저는 {self.name}입니다.'


p = Person('지민')
print(p)     # 저는 지민입니다.   ← __str__이 없었다면 <__main__.Person object at 0x...> 같은 기본 표현이 출력됨
```

> 이건 파이썬이 기본으로 제공하는 "객체를 문자열로 바꾸는 방법"을 내가 원하는 방식으로 **덮어쓴(override) 것**이라고 볼 수 있다. 나중에 상속을 배우면 "오버라이딩"이라는 용어로 더 정확히 정리될 개념이다.

> **💡 궁금증 — 파이썬도 자바의 `Object` 클래스처럼, 모든 클래스가 암묵적으로 상속받는 최상위 클래스 개념이 있나요?**
> 있다. 파이썬에서 정의하는 **모든 클래스는 기본적으로 `object` 클래스를 암묵적으로 상속**받는다.
> ```python
> class Person:
>     pass
>
> print(Person.__bases__)   # (<class 'object'>,)
> ```
> `class Person:`이라고만 써도 사실은 `class Person(object):`라고 쓴 것과 동일하게 동작한다. 그리고 방금 본 `__str__`, `__init__` 같은 매직 메서드들도 사실 전부 이 `object` 클래스에 **기본 구현이 이미 들어있는 것**을, 우리가 필요에 따라 **오버라이드해서 쓰는 것**이다. `__str__`을 안 만들었을 때 나오는 `<__main__.Person object at 0x...>`라는 출력이 바로 `object`가 제공하는 기본 `__str__` 구현이다. 개념적으로 자바의 `Object` 클래스와 정확히 같은 역할이라고 보면 된다.

## 12. 데코레이터 (Decorator)

**다른 함수의 코드를 유지한 채로 수정하거나 확장하기 위해 사용되는 함수.**

### 데코레이터 정의

```python
def my_decorator(func):
    def wrapper():
        # 함수 실행 전에 수행할 작업
        print('함수 실행 전')
        # 원본 함수 호출
        result = func()
        # 함수 실행 후에 수행할 작업
        print('함수 실행 후')
        return result
    return wrapper
```

### 데코레이터 사용

```python
@my_decorator
def my_function():
    print('원본 함수 실행')


my_function()
"""
함수 실행 전
원본 함수 실행
함수 실행 후
"""
```

> **동작 원리:** `@my_decorator`를 `my_function` 위에 붙이면, 파이썬은 실제로 `my_function = my_decorator(my_function)`을 실행한 것과 같다. 즉 `my_function`은 원래의 함수가 아니라, `my_decorator`가 반환한 **`wrapper` 함수로 바뀐다.** 그래서 `my_function()`을 호출하면 실제로는 `wrapper()`가 실행되면서, **원본 함수(`func`) 호출 앞뒤로 추가 동작**(`'함수 실행 전'`, `'함수 실행 후'` 출력)을 끼워 넣게 되는 것이다.
>
> 앞서 배운 `@classmethod`, `@staticmethod`도 사실 **파이썬이 미리 만들어둔 내장 데코레이터**다. 우리가 방금 만든 `my_decorator`처럼, "메서드가 원래 하려던 동작"에 "첫 번째 인자로 `cls`를 자동으로 넘겨준다"거나 "`self`/`cls` 없이 그냥 독립적으로 호출한다"는 **추가 규칙을 얹어주는 함수**인 셈이다.
