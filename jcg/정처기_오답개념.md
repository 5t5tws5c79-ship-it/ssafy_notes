# 정보처리기사 필기 오답 개념 정리

> 기존 오답노트를 기준으로 틀린 개념을 과목별로 정리한 문서이다.  
> 단순 정답 암기보다 **비슷한 개념 간 차이점**과 **오답 판별 기준**을 중심으로 정리한다.

---

## 1과목. 소프트웨어 설계

### 1. GoF 디자인 패턴

GoF 디자인 패턴은 목적에 따라 **생성·구조·행위 패턴**으로 분류한다.

| 분류 | 목적 | 패턴 |
|---|---|---|
| 생성 패턴 | 객체 생성 방식을 캡슐화 | Abstract Factory, Builder, Factory Method, Prototype, Singleton |
| 구조 패턴 | 클래스와 객체를 조합하여 구조 형성 | Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy |
| 행위 패턴 | 객체 간 책임과 상호작용 정의 | Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor |

#### 주요 오답 개념

- **Visitor**: 객체 구조는 변경하지 않고 새로운 연산을 추가하는 **행위 패턴**
- **Builder**: 복잡한 객체의 생성 과정과 표현 방법을 분리하는 **생성 패턴**
- **Prototype**: 기존 객체를 복제하여 새로운 객체를 만드는 **생성 패턴**
- **Bridge**: 구현부와 추상부를 분리하여 독립적으로 확장하는 **구조 패턴**

> **암기:** 생성은 객체를 만들고, 구조는 객체를 조립하며, 행위는 객체가 서로 행동하는 방법을 정의한다.

### 2. UML 관계

| 관계 | 의미 | 표기 |
|---|---|---|
| 연관 관계 | 두 클래스가 서로 관련됨 | 실선 |
| 의존 관계 | 한 클래스가 일시적으로 다른 클래스를 사용 | 점선 화살표 |
| 일반화 관계 | 상속 관계, `is-a` 관계 | 부모 방향의 속이 빈 삼각형 |
| 실체화 관계 | 인터페이스를 실제 클래스가 구현 | 점선 + 속이 빈 삼각형 |
| 집단화 관계 | 약한 부분-전체 관계, `part-of` | 전체 쪽에 속이 빈 마름모 |
| 포함 관계 | 강한 부분-전체 관계 | 전체 쪽에 채워진 마름모 |

#### 집단화와 포함 관계 비교

- **집단화(Aggregation)**
  - 전체 객체가 없어져도 부분 객체가 독립적으로 존재할 수 있다.
  - 예: 학과와 학생
- **포함(Composition)**
  - 전체 객체가 없어지면 부분 객체도 함께 소멸한다.
  - 예: 집과 방

> **핵심:** `is-a`는 일반화, `part-of`는 집단화 또는 포함 관계이다.

### 3. 객체지향 분석 방법론

| 방법론 | 주요 특징 |
|---|---|
| Coad-Yourdon | 객체와 클래스를 식별하고 구조·속성·서비스를 정의 |
| Rumbaugh | 객체 모델링 기법인 OMT 사용, 객체·동적·기능 모델로 분석 |
| Booch | 미시적 개발 과정과 거시적 개발 과정을 모두 사용 |
| Jacobson | Use Case를 중심으로 시스템 분석 |
| Wirfs-Brock | 분석과 설계 간 구분 없이 고객 명세를 평가하고 책임 중심으로 분석 |

#### Coad-Yourdon 분석 절차

1. 객체와 클래스 식별
2. 구조 식별
3. 주제(Subject) 정의
4. 속성 정의
5. 서비스 정의

> **문제 판별:** E-R 다이어그램을 사용하고 객체 식별부터 서비스 정의까지 수행하는 방법은 **Coad-Yourdon 방법**이다.

### 4. 코드 설계

코드는 데이터를 식별하고 분류하기 위해 일정한 규칙에 따라 부여하는 문자나 숫자이다.

| 코드 종류 | 설명 | 예시 |
|---|---|---|
| 순차 코드 | 일정한 순서대로 일련번호 부여 | 001, 002, 003 |
| 블록 코드 | 공통성이 있는 항목에 일정 범위의 코드 부여 | 100~199: 인사부 |
| 10진 코드 | 10진수 형태로 대분류·중분류·소분류 | 도서 분류 코드 |
| 그룹 분류 코드 | 각 자릿수에 특정한 분류 의미 부여 | 12-03-05 |
| 연상 코드 | 대상의 명칭이나 특성을 연상할 수 있게 부여 | TV, KR |
| 표의 숫자 코드 | 길이·넓이·무게 등 물리적 수치를 코드에 반영 | 150-80-20 |
| 합성 코드 | 둘 이상의 코드 방식을 조합 | 지역 코드 + 순차 코드 |

> 일정한 일련번호를 차례대로 부여하는 방식은 **순차 코드(Sequence Code)**이다.

### 5. 자료사전 표기 기호

| 기호 | 의미 |
|---|---|
| `=` | 자료의 정의, 구성 |
| `+` | 자료의 연결, 그리고(AND) |
| `[ ]` | 여러 항목 중 하나를 선택 |
| `( )` | 생략 가능, 선택적 요소 |
| `{ }` | 반복 |
| `* *` | 주석 또는 설명 |

#### 예시

`주문정보 = 주문번호 + 고객정보 + {상품정보} + (할인정보)`

- 상품정보는 반복될 수 있다.
- 할인정보는 생략할 수 있다.

> **암기:** 소괄호는 생략, 중괄호는 반복, 대괄호는 선택이다.

### 6. XP의 핵심 가치

XP(Extreme Programming)는 짧은 개발 주기와 지속적인 피드백을 강조하는 애자일 방법론이다.

XP의 5가지 핵심 가치는 다음과 같다.

1. **의사소통(Communication)**
2. **단순성(Simplicity)**
3. **피드백(Feedback)**
4. **용기(Courage)**
5. **존중(Respect)**

#### XP 주요 실천 방법

- Pair Programming
- Test-Driven Development
- Continuous Integration
- Small Releases
- Refactoring
- Collective Ownership

> **정형 분석**은 XP의 핵심 가치가 아니다.

## 2과목. 소프트웨어 개발

### 1. DRM 기술 요소

DRM(Digital Rights Management)은 디지털 콘텐츠의 저작권을 보호하고 허가된 사용자만 이용할 수 있도록 통제하는 기술이다.

#### 주요 DRM 기술 요소

- 콘텐츠 암호화
- 암호화 키 관리
- 사용자 및 장치 인증
- 권한 표현
- 정책 관리
- 크랙 방지 및 변조 방지
- 워터마킹
- 라이선스 관리
- 콘텐츠 식별 기술

#### DRM 구성 요소

| 구성 요소 | 역할 |
|---|---|
| 콘텐츠 제공자 | 콘텐츠를 제공하는 저작권자 |
| 콘텐츠 분배자 | 콘텐츠를 유통 |
| 콘텐츠 소비자 | 콘텐츠를 구매하고 이용 |
| 클리어링 하우스 | 라이선스 발급과 권한 관리 |
| DRM 컨트롤러 | 콘텐츠 이용 권한 통제 |
| 패키저 | 콘텐츠와 메타데이터를 패키징 |

> **방화벽**은 네트워크 접근 통제 기술이며 DRM의 직접적인 기술 요소가 아니다.

### 3. 반정규화의 테이블 추가 방법

반정규화는 조회 성능 향상을 위해 정규화된 데이터 구조를 의도적으로 중복하거나 통합하는 기법이다.

#### 반정규화 방법

1. 테이블 통합
2. 테이블 분할
3. 중복 테이블 추가
4. 중복 속성 추가
5. 파생 속성 추가

#### 중복 테이블 추가 방법

| 방법 | 설명 |
|---|---|
| 집계 테이블 추가 | 합계, 평균 등 통계 값을 미리 계산해 저장 |
| 진행 테이블 추가 | 업무 처리 상태나 진행 이력을 별도 저장 |
| 특정 부분 포함 테이블 추가 | 자주 조회하는 특정 열이나 행만 별도 테이블로 저장 |

> **빌드 테이블**은 일반적인 중복 테이블 추가 방법에 해당하지 않는다.

#### 반정규화 주의점

- 데이터 중복 증가
- 저장 공간 증가
- 삽입·수정·삭제 성능 저하 가능
- 데이터 일관성 유지가 어려워질 수 있음

## 3과목. 데이터베이스 구축

### 1. SQL 언어 분류

| 분류 | 목적 | 주요 명령어 |
|---|---|---|
| DDL | 데이터베이스 구조 정의 | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| DML | 데이터 조회 및 변경 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| DCL | 사용자 권한 부여 및 회수 | `GRANT`, `REVOKE` |
| TCL | 트랜잭션 제어 | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

> 기사 시험에서는 `COMMIT`, `ROLLBACK`을 DCL의 기능에 포함하여 출제하기도 한다.

#### 오답 방지

- `UPDATE`는 테이블 구조가 아니라 **데이터를 변경**하므로 DML이다.
- `ALTER`는 테이블 구조를 변경하므로 DDL이다.
- 논리적·물리적 구조 정의는 DDL의 기능이다.
- `GRANT`, `REVOKE`는 DCL이다.
- `SELECT`는 세부적으로 DQL로 부르기도 하지만 기사 시험에서는 일반적으로 DML에 포함한다.

### 2. 정규화

정규화는 데이터 중복과 이상 현상을 줄이기 위해 릴레이션을 분해하는 과정이다.

| 단계 | 조건 |
|---|---|
| 제1정규형(1NF) | 모든 속성값이 원자값이어야 함 |
| 제2정규형(2NF) | 1NF를 만족하고 부분 함수 종속 제거 |
| 제3정규형(3NF) | 2NF를 만족하고 이행 함수 종속 제거 |
| BCNF | 모든 결정자가 후보키 |
| 제4정규형(4NF) | 다치 종속 제거 |
| 제5정규형(5NF) | 조인 종속 제거 |

#### 부분 함수 종속

복합키의 일부 속성만으로 일반 속성이 결정되는 상태이다.

예를 들어 기본키가 `(학번, 과목코드)`일 때 다음 종속이 존재한다고 가정한다.

- `(학번, 과목코드) → 성적`
- `학번 → 학생이름`

`학생이름`이 기본키 전체가 아닌 `학번`에만 종속되므로 부분 함수 종속이다.

#### 완전 함수 종속

일반 속성이 후보키 전체에 의해서만 결정되는 상태이다.

> **1NF에서 2NF로 만들려면 부분 함수 종속을 제거하여 완전 함수 종속을 만족해야 한다.**

#### 이상 현상

- 삽입 이상
- 삭제 이상
- 갱신 이상

### 3. 무결성 제약 조건

| 종류 | 의미 |
|---|---|
| 개체 무결성 | 기본키는 `NULL`이나 중복 값을 가질 수 없음 |
| 참조 무결성 | 외래키는 참조 대상의 기본키 값 또는 `NULL`이어야 함 |
| 도메인 무결성 | 속성값은 정의된 도메인의 범위와 형식을 만족해야 함 |
| 사용자 정의 무결성 | 업무 규칙에 따라 사용자가 정의한 조건을 만족해야 함 |

#### 예시

- 기본키인 학번이 중복되거나 `NULL`이면 **개체 무결성 위반**
- 존재하지 않는 학과번호를 학생 테이블이 참조하면 **참조 무결성 위반**
- 나이 속성에 문자열이 입력되면 **도메인 무결성 위반**

> **핵심:** 기본키는 개체 무결성, 외래키는 참조 무결성과 관련된다.

| 단계 | 주요 작업 |

  - 레코드 저장 구조 결정
  - 인덱스와 접근 경로 결정

  - 저장 공간과 성능 고려

> **레코드 집중 분석은 물리적 설계 단계의 작업**이다.

### 5. 로킹 단위와 오버헤드

로킹은 하나의 트랜잭션이 데이터에 접근하는 동안 다른 트랜잭션의 접근을 제한하는 병행 제어 기법이다.

| 로킹 단위 | 병행성 | 잠금 개수 | 관리 오버헤드 |
|---|---:|---:|---:|
| 작음 | 높음 | 많음 | 증가 |
| 큼 | 낮음 | 적음 | 감소 |

#### 예시

- 행 단위 잠금: 병행성은 높지만 많은 잠금 정보를 관리해야 한다.
- 테이블 단위 잠금: 관리가 간단하지만 다른 트랜잭션의 접근이 크게 제한된다.

> **로킹 단위가 작아지면 병행성은 증가하지만 오버헤드도 증가한다.**

### 6. 분산 데이터베이스 투명성

분산 데이터베이스 투명성이란 사용자가 데이터의 분산 상태를 의식하지 않고 하나의 데이터베이스처럼 사용할 수 있게 하는 성질이다.

| 투명성 | 의미 |
|---|---|
| 위치 투명성 | 데이터가 어느 지역에 저장되어 있는지 알 필요가 없음 |
| 중복 투명성 | 동일 데이터가 여러 장소에 복제되어 있어도 알 필요가 없음 |
| 분할 투명성 | 데이터가 여러 조각으로 분할되어 있어도 하나처럼 사용 |
| 병행 투명성 | 여러 사용자가 동시에 접근해도 일관성 유지 |
| 장애 투명성 | 일부 지역이나 통신에 장애가 발생해도 데이터 무결성과 트랜잭션 일관성 유지 |

> 특정 지역에서 장애가 발생해도 데이터 무결성을 보장하는 성질은 **장애 투명성**이다.

### 7. 후보키 조건

후보키는 튜플을 유일하게 식별할 수 있는 최소 속성 집합이다.

#### 후보키의 두 가지 조건

1. **유일성**
   - 모든 튜플을 서로 다르게 식별할 수 있어야 한다.
2. **최소성**
   - 식별에 필요하지 않은 속성을 제거하면 유일성을 잃어야 한다.

#### 키 종류

| 키 | 설명 |
|---|---|
| 슈퍼키 | 유일성을 만족하는 속성 집합 |
| 후보키 | 유일성과 최소성을 모두 만족 |
| 기본키 | 후보키 중 대표로 선택한 키 |
| 대체키 | 후보키 중 기본키로 선택되지 않은 키 |
| 외래키 | 다른 테이블의 기본키를 참조하는 키 |

> 슈퍼키에서 불필요한 속성을 제거하여 **최소성**까지 만족하면 후보키가 된다.

#### 교착상태 발생 조건

다음 네 조건이 모두 만족하면 교착상태가 발생할 수 있다.

1. 상호 배제
2. 점유와 대기
3. 비선점
4. 순환 대기

#### 해결 기법

| 기법 | 설명 |
|---|---|
| 예방 | 교착상태 발생 조건 중 하나를 사전에 제거 |
| 회피 | 안전 상태를 유지할 수 있을 때만 자원 할당 |
| 발견 | 교착상태 발생을 허용한 후 검사 |
| 복구 | 프로세스 종료 또는 자원 선점으로 해결 |

- 대표적인 **교착상태 회피 기법**
- 프로세스의 최대 자원 요구량을 미리 알고 있어야 한다.
- 자원 할당 후에도 안전 순서가 존재할 때만 자원을 할당한다.

> **은행가 알고리즘 = 회피(Avoidance)**

### 6. ARP와 RARP

| 프로토콜 | 변환 방향 | 설명 |
|---|---|---|
| ARP | IP 주소 → MAC 주소 | 목적지 IPv4 주소에 대응하는 MAC 주소 확인 |
| RARP | MAC 주소 → IP 주소 | MAC 주소를 이용하여 자신의 IP 주소 확인 |

#### ARP 처리 과정

1. ARP 요청을 브로드캐스트한다.
2. 해당 IP를 가진 장치가 자신의 MAC 주소를 응답한다.
3. 결과를 ARP 캐시에 저장한다.

#### 참고

- RARP는 현재 거의 사용하지 않는다.
- RARP의 역할은 BOOTP와 DHCP가 대체하였다.
- IPv6에서는 ARP 대신 NDP를 사용한다.

> **암기:** ARP는 IP에서 MAC, RARP는 그 반대이다.

### 7. 페이지 교체 알고리즘

페이지 교체 알고리즘은 페이지 부재 발생 시 어떤 페이지를 제거할지 결정한다.

| 알고리즘 | 제거 기준 |
|---|---|
| FIFO | 가장 먼저 메모리에 들어온 페이지 |
| OPT | 앞으로 가장 오랫동안 사용되지 않을 페이지 |
| LRU | 가장 오랫동안 사용되지 않은 페이지 |
| LFU | 사용 횟수가 가장 적은 페이지 |
| NUR | 최근 사용 여부와 수정 여부를 이용 |

#### FIFO 계산 방법

1. 프레임 수만큼 빈칸을 준비한다.
2. 참조 페이지가 프레임에 있으면 Hit이다.
3. 참조 페이지가 없으면 Page Fault이다.
4. 빈 프레임이 있으면 페이지를 삽입한다.
5. 빈 프레임이 없으면 가장 먼저 들어온 페이지를 교체한다.
6. Hit가 발생한 경우 FIFO 순서는 변경하지 않는다.

#### 계산 표 양식

| 순서 | 참조 페이지 | 프레임 1 | 프레임 2 | 프레임 3 | Hit/Fault |
|---:|---:|---:|---:|---:|---|
| 1 |  |  |  |  |  |
| 2 |  |  |  |  |  |
| 3 |  |  |  |  |  |

#### FIFO 특징

- 구현이 단순하다.
- 자주 사용되는 페이지도 오래되었다는 이유로 제거될 수 있다.
- 프레임 수가 증가했는데 페이지 부재가 증가하는 **Belady의 모순**이 발생할 수 있다.

> 계산 문제는 반드시 프레임 표를 작성하고 Page Fault 개수를 직접 세어야 한다.

### 8. IPv4와 IPv6

| 구분 | IPv4 | IPv6 |
|---|---|---|
| 주소 길이 | 32비트 | 128비트 |
| 주소 표기 | 점으로 구분한 10진수 | 콜론으로 구분한 16진수 |
| 기본 헤더 | 20~60바이트 | 40바이트 |
| 헤더 체크섬 | 존재 | 없음 |
| 브로드캐스트 | 지원 | 지원하지 않음 |
| 멀티캐스트 | 지원 | 지원 |
| 애니캐스트 | 제한적 | 지원 |
| 자동 설정 | DHCP 등 이용 | 자동 주소 설정 기능 강화 |
| 단편화 | 송신자와 라우터가 수행 가능 | 송신자만 수행 |
| 주소 공간 | 약 43억 개 | 매우 큼 |

#### 패킷 크기 주의

- IPv4 패킷의 전체 길이는 16비트 필드로 표현하며 최대 65,535바이트이다.
- IPv4 패킷이 항상 64KB로 고정되는 것은 아니다.
- IPv6 기본 헤더의 Payload Length 필드도 일반적으로 최대 65,535바이트의 페이로드를 표현한다.
- IPv6는 Jumbo Payload 옵션을 이용하면 이보다 큰 페이로드를 사용할 수 있다.

> 따라서 **“IPv6 패킷은 64KB로 고정된다”는 설명은 틀리다.**  
> 단, “IPv6는 패킷 크기에 아무 제한도 없다”는 표현도 정확하지 않다.

### 9. 프로세스 상태

#### 기본 프로세스 상태

| 상태 | 설명 |
|---|---|
| 생성(New) | 프로세스가 생성되는 중 |
| 준비(Ready) | CPU를 할당받기 위해 대기 |
| 실행(Running) | CPU를 할당받아 명령 수행 |
| 대기(Blocked/Waiting) | 입출력이나 이벤트 완료 대기 |
| 종료(Terminated) | 실행 완료 |

일부 교재에서는 제출과 접수를 포함하여 다음과 같이 표현한다.

`제출 → 접수 → 준비 → 실행 → 대기 → 종료`

#### 주요 상태 전이

- 준비 → 실행: 디스패치
- 실행 → 준비: 시간 할당량 만료 또는 선점
- 실행 → 대기: 입출력 요청
- 대기 → 준비: 입출력 완료
- 실행 → 종료: 작업 완료

> `Request`는 일반적인 프로세스 상태가 아니라 요청 동작이나 이벤트를 의미한다.

### 11. 전송 계층의 역할

전송 계층은 송신 프로세스와 수신 프로세스 사이의 **종단 간 데이터 전송**을 담당한다.

#### 주요 기능

- 종단 간 연결 설정 및 해제
- 데이터 분할 및 재조립
- 포트 번호를 이용한 프로세스 식별
- 다중화와 역다중화
- 흐름 제어
- 오류 검출 및 복구
- 혼잡 제어
- 순서 제어

#### TCP와 UDP

| 구분 | TCP | UDP |
|---|---|---|
| 연결 방식 | 연결형 | 비연결형 |
| 신뢰성 | 높음 | 보장하지 않음 |
| 순서 보장 | 지원 | 지원하지 않음 |
| 흐름·혼잡 제어 | 지원 | 지원하지 않음 |

| 예시 | HTTP, FTP, SMTP | DNS, 스트리밍, VoIP |

> 오류 복구와 신뢰성 있는 전송은 주로 TCP가 제공한다.

## 5과목. 정보시스템 구축관리

### 1. 라우팅 프로토콜

| 구분 | RIP | OSPF | EIGRP |
|---|---|---|---|
| 방식 | 거리 벡터 | 링크 상태 | 고급 거리 벡터 또는 하이브리드 |
| 알고리즘 | Bellman-Ford | Dijkstra SPF | DUAL |
| 메트릭 | 홉 수 | 비용 | 대역폭, 지연 등 |
| 최대 홉 수 | 15홉 | 해당 없음 | RIP보다 큰 범위 지원 |
| 특징 | 단순하지만 느린 수렴 | 빠른 수렴, Area 사용 | 빠른 수렴, Cisco 중심 |

#### RIP

- 최대 홉 수는 15이다.
- 16홉은 도달할 수 없는 네트워크를 의미한다.
- 주기적으로 라우팅 정보를 교환한다.
- 소규모 네트워크에 적합하다.

#### OSPF

- 링크 상태 정보를 기반으로 최단 경로를 계산한다.
- 대규모 네트워크를 Area로 분할한다.
- RIP보다 수렴 속도가 빠르다.

#### EIGRP

- DUAL 알고리즘을 사용한다.
- 대역폭과 지연 등을 기준으로 경로를 선택한다.
- 전통적으로 Cisco 장비에서 사용한다.

> **최대 홉 수가 15로 제한되는 프로토콜은 RIP이다.**

---

### 2. PICONET

PICONET은 Bluetooth나 UWB 등의 근거리 무선 기술을 이용하여 형성하는 소규모 무선 네트워크이다.

#### Bluetooth PICONET

- 하나의 중앙 장치가 네트워크를 관리한다.
- Bluetooth Classic에서는 최대 7개의 활성 종속 장치가 참여할 수 있다.
- 여러 PICONET을 연결한 구조를 **SCATTERNET**이라고 한다.

#### 관련 용어

| 용어 | 설명 |
|---|---|
| WPAN | 개인 영역의 근거리 무선 네트워크 |
| PICONET | Bluetooth 기반의 소규모 네트워크 |
| SCATTERNET | 여러 PICONET을 연결한 네트워크 |
| WLAN | Wi-Fi를 이용하는 무선 근거리 네트워크 |

### 3. COCOMO 모형

COCOMO는 소프트웨어의 규모를 바탕으로 개발 노력과 비용을 산정하는 모델이다.

#### 개발 유형

| 유형 | 특징 |
|---|---|
| Organic | 5만 라인 이하의 비교적 작고 단순한 프로젝트 |
| Semi-detached | 중간 규모이며 경험자와 비경험자가 혼합된 프로젝트 |
| Embedded | 하드웨어·실시간·규제 등 복잡한 제약이 많은 프로젝트 |

> **5만 라인 이하의 소규모 소프트웨어는 Organic 유형이다.**

#### COCOMO 모형 단계

| 모형 | 특징 |
|---|---|
| 기본형 | 소프트웨어 크기만 이용하여 비용 산정 |
| 중간형 | 크기와 함께 제품·인력·환경 등의 비용 요인 반영 |
| 상세형 | 개발 단계별로 비용 요인을 세부 적용 |

---

### 4. Putnam 모형

Putnam 모형은 소프트웨어 생명주기 동안의 인력 분포를 이용하여 개발 비용과 기간을 산정한다.

#### 특징

- **Rayleigh-Norden 곡선**을 사용한다.
- 시간에 따른 인력 투입 분포를 표현한다.
- SLIM 도구의 기반이 된다.
- 개발 기간을 무리하게 단축하면 필요한 인력과 비용이 급격히 증가한다.

> **Rayleigh-Norden 곡선을 사용하는 비용 산정 모형은 Putnam 모형이다.**

#### COCOMO와 비교

| 구분 | COCOMO | Putnam |
|---|---|---|
| 중심 기준 | 코드 규모와 비용 요인 | 생명주기와 인력 분포 |
| 대표 개념 | Organic, Semi-detached, Embedded | Rayleigh-Norden 곡선 |
| 관련 도구 | COCOMO 모형 | SLIM |

### 5. 소프트웨어 생명주기 모형

| 모형 | 핵심 특징 | 단점 |
|---|---|---|
| 폭포수 | 단계를 순차적으로 진행 | 요구사항 변경 반영이 어려움 |
| 프로토타입 | 시제품으로 요구사항 확인 | 시제품에 과도한 시간 투입 가능 |
| 나선형 | 위험 분석을 중심으로 반복 개발 | 관리가 복잡하고 비용이 증가할 수 있음 |

#### 폭포수 모형

- 분석, 설계, 구현, 테스트, 운영을 순차적으로 진행한다.
- 각 단계가 명확하고 문서화가 중요하다.
- 이전 단계로 돌아가기 어렵다.
- 요구사항이 명확하고 변경이 적은 프로젝트에 적합하다.

> “요구사항을 쉽게 반영할 수 있다”는 폭포수 모형의 특징이 아니다.

#### 프로토타입 모형

- 초기 시제품을 제작하여 사용자 요구사항을 확인한다.
- 요구사항이 불명확한 경우 효과적이다.
- 폐기형과 진화형 프로토타입으로 구분할 수 있다.

#### 나선형 모형

Boehm이 제안한 위험 중심의 반복적 개발 모형이다.

1. 계획 수립
2. 위험 분석
3. 개발 및 검증
4. 고객 평가

> **위험 관리와 프로토타입 반복을 강조하는 모형은 나선형 모형이다.**

### 6. 정보보안 침해 공격 유형

| 공격 유형 | 설명 |
|---|---|
| Ransomware | 파일을 암호화하거나 시스템을 잠근 후 금전을 요구 |
| Smishing | SMS 문자 메시지를 이용한 피싱 |
| Phishing | 가짜 이메일이나 사이트로 개인정보 탈취 |
| Pharming | 사용자를 가짜 사이트로 강제 이동시켜 정보 탈취 |
| Trojan Horse | 정상 프로그램처럼 위장한 악성 프로그램 |
| Worm | 네트워크를 통해 스스로 복제하고 전파 |

| Spyware | 사용자 정보를 몰래 수집 |

#### 주요 구분

- **랜섬웨어**: 암호화 또는 시스템 잠금 후 금전 요구
- **스미싱**: 문자 메시지에 포함된 링크를 이용
- **트로이 목마**: 정상 프로그램으로 위장하며 일반적으로 스스로 복제하지 않음
- **웜**: 다른 프로그램에 기생하지 않고 스스로 복제 가능

### 7. 백도어 탐지 방법

백도어는 정상적인 인증 절차를 우회하여 시스템에 접근할 수 있게 만든 비정상적인 통로이다.

#### 백도어 탐지 방법

- 예상하지 못한 열린 포트 확인
- 비정상적인 프로세스 확인
- SetUID, SetGID 파일 검사
- 시스템 로그 및 로그인 기록 분석
- 파일 크기와 해시값 비교
- 시스템 파일 무결성 검사
- 비정상적인 네트워크 연결 확인
- 시작 프로그램과 예약 작업 검사
- 레지스트리 및 설정 변경 확인

> 백도어는 비정상적으로 열린 포트를 통해 동작할 수 있으므로 **열린 포트**를 검사해야 한다.  
> 단순히 “닫힌 포트를 확인한다”는 것은 대표적인 백도어 탐지 방법이 아니다.

### 8. Hadoop

Hadoop은 대용량 데이터를 여러 컴퓨터에 분산 저장하고 처리하기 위한 오픈 소스 프레임워크이다.

#### Hadoop 핵심 구성 요소

| 구성 요소 | 역할 |
|---|---|
| HDFS | 대용량 파일을 여러 노드에 분산 저장 |
| MapReduce | 데이터를 병렬로 분산 처리 |
| YARN | 클러스터 자원 및 작업 스케줄 관리 |
| Hadoop Common | 공통 라이브러리와 유틸리티 제공 |

#### 특징

- 분산 저장
- 병렬 처리
- 대용량 데이터 처리
- 노드 장애에 대한 내결함성
- 일반 서버를 이용한 수평 확장

#### 관련 생태계

- Hive: SQL과 유사한 형태로 데이터 분석
- HBase: 분산 NoSQL 데이터베이스
- Pig: 데이터 처리 스크립트
- Sqoop: 관계형 데이터베이스와 Hadoop 간 데이터 전송
- Spark: 별도 처리 엔진이지만 HDFS 및 YARN과 함께 사용 가능

### 9. Tripwire

Tripwire는 시스템 파일과 설정 파일의 변경 여부를 탐지하는 **호스트 기반 무결성 검사 도구**이다.

#### 동작 원리

1. 정상 상태의 파일 해시값과 속성을 기준값으로 저장한다.
2. 주기적으로 현재 파일 상태를 검사한다.
3. 기준값과 다른 변경 사항이 발견되면 관리자에게 알린다.

#### 탐지 가능한 항목

- 파일 내용 변경
- 파일 크기 변경
- 권한 변경
- 소유자 변경
- 설정 파일 변경
- 악성코드에 의한 시스템 파일 변조

#### 관련 도구 비교

| 도구 | 용도 |
|---|---|
| Tripwire | 파일 및 시스템 무결성 검사 |
| Snort | 네트워크 기반 침입 탐지 |
| Nmap | 포트와 네트워크 스캔 |
| Tcpdump | 네트워크 패킷 분석 |
| Netcat | 네트워크 연결 및 데이터 송수신 |

> **침입으로 인한 파일·설정 변경 분석에는 Tripwire를 사용한다.**

### 10. 프로젝트 테일러링 기준

테일러링은 표준 개발 방법론을 프로젝트 특성에 맞게 선택하거나 조정하는 작업이다.

#### 내부 기준

프로젝트와 조직 내부의 특성을 기준으로 한다.

- 프로젝트 규모
- 목표 시스템 환경
- 요구사항의 복잡도
- 시스템의 보안 수준
- 기술적 난이도
- 개발 인력의 경험과 역량
- 일정과 비용
- 조직의 개발 환경
- 위험 수준

#### 외부 기준

조직 외부에서 요구되는 규정과 조건을 기준으로 한다.

- 법률과 규제
- 국제 표준
- 국가 표준
- 품질 인증 기준
- 보안 인증 기준
- 계약 조건
- 고객사의 표준과 요구사항

> **국제 표준 품질 기준은 내부 기준이 아니라 외부 기준이다.**

- [ ] 순차 코드는 일정한 일련번호를 부여한다.
- [ ] 자료사전에서 `( )`는 생략 가능, `{ }`는 반복이다.

- [ ] `UPDATE`는 DML이다.
- [ ] 2NF는 부분 함수 종속을 제거한다.
- [ ] 기본키는 `NULL`과 중복을 허용하지 않는다.
- [ ] 로킹 단위가 작아지면 병행성과 오버헤드가 증가한다.

- [ ] 프로세스·메모리·입출력 관리는 커널의 역할이다.
- [ ] TCP는 전송 계층 프로토콜이다.
- [ ] 하나의 프로세스는 여러 스레드를 가질 수 있다.
- [ ] 은행가 알고리즘은 교착상태 회피 기법이다.

- [ ] FIFO는 가장 먼저 들어온 페이지를 교체한다.
- [ ] IPv6 패킷 크기는 64KB로 고정되지 않는다.
- [ ] COBOL은 스크립트 언어가 아니다.
- [ ] RIP의 최대 홉 수는 15이다.
- [ ] COCOMO Organic은 소규모 프로젝트 유형이다.
- [ ] Putnam 모형은 Rayleigh-Norden 곡선을 사용한다.
- [ ] 나선형 모형은 위험 분석을 강조한다.
- [ ] 랜섬웨어는 시스템을 잠그거나 파일을 암호화한 후 금전을 요구한다.
