# CSS 레이아웃 정리 (Layout)

## 1. 박스 타입 (Display Type)

### 블록(Block) 타입

```css
.index { display: block; }
```

**블록은 다른 것들이 끼어들지 않는다.** 큰 구조를 잡을 때 사용한다.

### 블록 타입의 특징

- **항상 새로운 행으로 나뉜다.** 한 줄 전체를 차지하며, 다른 요소가 옆에 올 수 없다.
- `width`, `height`, `margin`, `padding` **모두 사용 가능**하다.
- `padding`, `margin`, `border`로 인해 **다른 요소를 상자로부터 밀어낸다.**
- `width`를 지정하지 않으면, 박스는 **인라인 방향(좌우)으로 사용 가능한 공간을 모두 차지**한다.

> **방향 용어 정리:** **인라인 = 좌우**, **블록 = 상하** 방향을 가리킨다.

### 대표적인 블록 타입 태그

```
h1~h6, p, div, ul, li
```

**`div`가 대표 태그다.** 의미를 크게 부여하지 않고, **블록적인 요소만 구성**해주는 태그다.

> **💡 플러터 비유:** "마치 플러터의 `SizedBox` 같은 건가?" — 개념적으로 비슷하다. `div`는 그 자체로 특별한 의미(제목, 문단 등)를 갖지 않고 **레이아웃 구조를 잡기 위한 순수한 컨테이너**라는 점에서, 플러터의 `Container`/`SizedBox`가 하는 역할(자체 의미 없이 배치·크기 조절용 상자)과 정신이 닮았다. 다만 `div`는 항상 "블록"이라는 특정 배치 성격(줄 전체 차지, 세로 방향으로 쌓임)을 갖고 시작한다는 점이 다르다.

---

### 인라인(Inline) 타입

**문장 안에 단어처럼, 흐름에 따라 자연스럽게 배치되는 요소.** 마치 **형광펜으로 칠한 것** 같은 느낌.
```
a, img, span, strong
```

### 인라인 타입의 특징

- `width`, `height` **사용 못함.**
- **수직 방향**(위아래) 여백은 적용되지만, **다른 요소를 밀어낼 수는 없다.**
- **수평 방향**(좌우) 여백은 적용되어 **다른 요소를 밀어낼 수 있다.** (`padding`, `margin`, `border` 모두 좌우로는 영향을 줌)

### 인라인 대표 타입 — `span`

> **"이게 `SizedBox`다"** — `div`가 블록의 대표라면, **`span`이 인라인의 대표**다. `div`는 큰 구조(줄 전체를 차지하는 블록)를 잡는 도구이고, `span`은 **문장 흐름 속에서 특정 부분만** 감싸는 도구라는 점에서 정확히 대응 관계다.

- 자체적으로는 **시각적 변화가 없다.**
- **텍스트 일부를 조작**할 때, 즉 특정 단어나 구문에만 스타일을 적용하고 싶을 때 유용하다.

---

### 노멀 플로우 (Normal Flow)

**일반적인 흐름, 즉 레이아웃을 별도로 변경하지 않았을 때 웹 페이지 요소가 배치되는 기본 방식.**

> **비유 — 워드 문서:** **엔터(Enter)는 블록**과 같고, **스페이스(Space)는 인라인**과 같다고 볼 수 있다. 엔터를 치면 무조건 새 줄로 넘어가고(블록의 "항상 새 행"과 동일), 스페이스는 같은 줄 안에서 흐름을 이어간다(인라인의 "흐름에 따라 배치"와 동일).

---

### 인라인 블록(Inline-Block) 타입

**인라인과 블록의 특징을 모두 가진 특별한 `display` 속성 값.**

> **비유 — 줄 서 있는 사람들:** 인라인 블록 타입은 줄 서 있는 사람들과 같다. 사람들은 **한 줄로 서있지만**, 사람마다 **키와 덩치가 다르며 각자의 공간(자리)을 가지고 있다.** 즉 인라인처럼 옆으로 나란히 배치되면서도, 블록처럼 각자 크기를 가진다.

### 특징

- **줄바꿈 없이** 크기 지정이 가능하다.
- `width`, `height` **사용 가능.**
- `padding`, `margin`, `border`로 인해 **위아래 요소가 상자에서 밀려난다.** (인라인과 달리 수직 방향으로도 밀어낼 수 있음)

---

### None 타입

**요소를 화면에 표시하지 않는다.** 마치 **후보 선수**와 같다 — 존재하지만 경기(화면)에는 나오지 않는다.

- 화면에 **아예 그려지지 않는다.** (공간조차 차지하지 않음)
- 나중에 **반응형 웹 / JS와 함께 쓸 때** 주로 사용된다.

> **활용 예시:** 어떤 웹사이트를 볼 때 창을 줄이다 보면, 어느 지점에서 뷰가 확 바뀌는 걸 본 적 있을 것이다. **기존 뷰가 사라지고 특정 임계 사이즈 이하일 때 다른 뷰가 튀어나와야 하는** 상황 — 이럴 때 특정 **임계점(breakpoint)을 넘어서는 순간 `none`을 해제하거나 부여**하는 방식으로 활용된다.

> **(참고) 플렉스(Flex) 타입은 뒤쪽 챕터에서 별도로 다룬다.**

## 2. CSS 포지션 (Position)

**CSS 레이아웃이란?** 각 요소의 **위치와 크기를 조정**해서 원하는 디자인을 만드는 것. (블록, 인라인도 넓게 보면 레이아웃의 일부)

**CSS 포지션이란?** 요소를 **노멀 플로우에서 제거**하여 **다른 위치로 배치**하는 것. 다른 요소 위에 올리기, 화면의 특정 위치에 고정시키기 등에 사용한다.

- **핵심 속성:** `position` — `static`, `relative`, `absolute`, `fixed`, `sticky`
- 포지션은 요소의 **이동 방향**(상하좌우)뿐 아니라, **겹치는 요소들이 쌓이는 순서(z축)**도 조절할 수 있다.

---

## 3. 포지션의 유형 5가지

### 3-1. `static` — 기본값

- **노멀 플로우에 따라 배치**된다.
- `top`, `left`, `right`, `bottom` 속성이 **적용되지 않는다.**
- **기본값** — 아무것도 설정하지 않은 기본 상태.

### 3-2. `relative` — 상대 위치

**기준점(본인이 `static`일 때의 위치)을 기준으로 이동**한다.

- **노멀 플로우를 유지하면서 이동만** 한다. 즉, `static`일 때와 **실제로 차지하는 공간(자리)은 동일**하다.

> **💡 플러터 비유:** "트랜스폼(transform) 같은 거랑 같은 거구나" — 정확한 감각이다. `position: relative`로 이동해도 **원래 자리는 그대로 비워둔 채(공간을 차지한 채) 시각적으로만 이동**한다는 점에서, 레이아웃 계산에는 영향을 주지 않고 그리기 단계에서만 위치를 옮기는 `Transform`(예: `Transform.translate`)과 개념적으로 유사하다. 레이아웃을 다시 계산시키지 않는다는 게 공통점.

### 3-3. `absolute` — 절대 위치

**노멀 플로우에서 완전히 뜯어내서**, **가장 가까운 `relative`(또는 다른 position이 지정된) 부모 요소를 기준**으로 이동한다.

- 그런 부모 요소가 없다면, **`<body>` 태그를 기준**으로 한다.
- 원래 차지하던 **문서 내 공간이 사라진다.** (다른 요소들이 그 자리를 채우며 이동함)

> **활용 예시:** 이미지에 뱃지(badge)를 붙이는 UI. **이미지가 `relative`**, **뱃지가 `absolute`**로 설정되어, 이미지를 기준으로 뱃지가 원하는 모서리에 딱 붙게 만들 수 있다.

### 3-4. `fixed` — 고정 위치

**노멀 플로우에서 제거**되고, **뷰포트(viewport, 화면에 보이는 영역) 기준**으로 이동한다.

- **스크롤을 해도 항상 같은 위치**에 고정되어 있다.
- 예: **플로팅 액션 버튼(FAB)** 등.

### 3-5. `sticky` — 끈적한 위치

**`relative`와 `fixed`를 결합한 속성.**

- **스크롤 위치가 임계점에 도달하기 전**에는 `relative`처럼 동작한다. (원래 자리를 지킴)
- **스크롤 위치가 임계점에 도달하면** `fixed`처럼 **화면에 고정**된다.

> **활용 예시:** 페이지를 스크롤하면 함께 스크롤 되다가, **어느 지점에서 갑자기 화면 상단(또는 지정 위치)에 딱 붙어서** 계속 그 자리에 머무는 UI(내비게이션 바 등)가 바로 이 `sticky`다. 다시 스크롤을 반대로 돌리면(원래 자리 범위로 돌아가면), 다시 **본인의 `relative` 위치로 돌아가 붙는다.**

## 4. z-index

**정수 값을 사용해 z축(쌓이는) 순서를 지정**한다. **값이 클수록 요소가 위(앞쪽)에 쌓인다.**

- **기본값은 `auto`.** 부모 요소의 `z-index`에 영향을 받는다.
- `z-index` 값은 **같은 부모 안에서만 비교**된다. 값이 같으면 **HTML 문서에 작성된 순서대로** 쌓인다. (나중에 작성된 게 위로)
- ⚠️ **부모의 `z-index`가 낮으면, 자식의 `z-index`가 아무리 높아도 부모보다 더 높이 올라갈 수 없다.** (자식은 부모가 만든 "쌓임 맥락(stacking context)" 안에서만 순서를 다툰다)

## 5. 플렉스박스 (Flexbox)

**"박스 안에 박스를 배치"**하는 레이아웃 방식. `display` 값으로는 **플렉스박스**라는 이너(inner) 디스플레이 타입을 부여한다.

**요소를 행과 열 형태로 배치하는 1차원(one-dimensional) 레이아웃 방식.**

> **비유:** "책들을 왼쪽에 붙여줘", "서로 같은 간격으로 띄워줘" 같은 명령을 손쉽게 내릴 수 있는 배치 시스템.

> **💡 플러터 비유:** "플러터 형식이다, 맞지?" — 맞다. 플러터의 `Row`/`Column` + `MainAxisAlignment`/`CrossAxisAlignment` 시스템이 바로 CSS 플렉스박스의 개념을 그대로 가져다 쓴 것이다. **주축(main axis)/교차축(cross axis)** 개념도 동일하고, `justify-content` ↔ `MainAxisAlignment`, `align-items` ↔ `CrossAxisAlignment`처럼 **거의 1:1로 대응**된다. 그래서 플렉스박스를 이해하면 플러터의 Row/Column 정렬 시스템도 자연스럽게 이해된다 (반대도 마찬가지).

플렉스박스는 요소를 행과 열 형태로 배치하는 1차원 레이아웃 방식으로, **공간의 배열과 정렬**을 다룬다.

---

## 6. 플렉스박스의 구성 요소

| 용어 | 역할 |
|------|------|
| **메인 축 (Main Axis)** | 플렉스 아이템이 배치되는 **주된 방향** |
| **교차 축 (Cross Axis)** | 메인 축에 **수직인 방향** |
| **플렉스 컨테이너 (Flex Container)** | `display: flex`가 설정된 **부모 요소** |
| **플렉스 아이템 (Flex Item)** | 컨테이너의 **1차 자식**들. 배치의 대상이 됨 |

> **학습 팁:** 처음엔 "**메인 축**"만 확실히 기억하자. 교차 축은 항상 메인 축에 **수직인 나머지 방향**이므로, 메인 축만 알면 자동으로 따라온다.

### 플렉스 컨테이너

`display: flex` 또는 `display: inline-flex`가 설정된 **부모 요소.**

- 컨테이너의 **1차 자식이 플렉스 아이템**이 된다.
- 플렉스박스 속성 값들을 사용하여 **자식 요소(플렉스 아이템)를 배치하는 주체**다.

### 플렉스박스 속성 목록
```
display, flex-direction, flex-wrap,
justify-content, align-items, align-content,
align-self, flex-grow, flex-basis, order
```

---

## 7. 플렉스 컨테이너 속성 하나씩

### `display: flex`

**1단계 — 플렉스 컨테이너로 지정.**

```css
.container {
  display: flex;
}
```

이 한 줄만으로 다음이 **기본값**으로 자동 적용된다:

- 방향은 **row(가로)**로 생기고, 안의 아이템은 `justify-content: flex-start`(메인축 시작점)로 쌓인다.
- `align-items: stretch`(교차축 방향으로 컨테이너 크기만큼 늘어남)가 기본이다.

### `flex-direction`

메인 축의 **방향**을 결정한다.

```css
flex-direction: row;             /* 기본값 — 가로, 왼→오 */
flex-direction: row-reverse;     /* 가로, 오→왼 */
flex-direction: column;          /* 세로, 위→아래 */
flex-direction: column-reverse;  /* 세로, 아래→위 */
```

### `flex-wrap`

컨테이너의 **한 행에 아이템이 다 들어가지 않을 경우, 다음 행으로 넘길지 여부**를 설정한다.

- `flex-wrap: wrap`을 **켜두면 자동으로 줄바꿈**된다. (기본값은 `nowrap` — 줄바꿈 없이 억지로 한 줄에 다 구겨 넣음)

### `justify-content` — 메인 축 정렬

```css
justify-content: flex-start;   /* 메인축 시작점에 몰림 */
justify-content: center;       /* 메인축 가운데 정렬 */
justify-content: flex-end;     /* 메인축 끝점에 몰림 */
justify-content: space-between; /* 아이템 사이 균등 간격 (양끝은 붙음) */
justify-content: space-around;  /* 아이템 둘레 균등 간격 */
justify-content: space-evenly;  /* 모든 간격 완전 균등 */
```

### `align-content` vs `align-items` — 둘 다 "align"이지만 다르다

**공통점:** 둘 다 이름에 "align"이 붙은 애들은 **교차 축**을 다룬다.

**차이점:**

| | 목적 |
|---|------|
| **`align-content`** | 여러 **줄(row/line)들 사이의 공간 배분**이 목적. (즉, `flex-wrap`으로 여러 줄이 생겼을 때 그 **줄들 전체를** 교차축 방향으로 어떻게 배치할지) |
| **`align-items`** | **한 줄짜리 정렬.** (한 줄 안에서 아이템들을 교차축 방향으로 어떻게 정렬할지) |

```css
align-content: flex-start;   /* 여러 줄이 위로 쏠림 */
align-content: center;       /* 여러 줄이 수직 가운데 정렬 */
align-content: flex-end;     /* 여러 줄이 아래쪽에 붙음 */

align-items: flex-start;     /* 한 줄 안 아이템들이 위로 붙음 */
align-items: center;         /* 한 줄 안 아이템들이 가운데 정렬 */
align-items: flex-end;       /* 한 줄 안 아이템들이 아래로 붙음 */
```

### `align-self` — 컨테이너가 아니라 자식이 스스로 쓰는 속성

**지금까지의 모든 속성(`justify-content`, `align-items`, `align-content`)은 부모(컨테이너)를 컨트롤하는 속성**이었다. 반면 **`align-self`는 호출자 본인(개별 아이템)에게만** 적용된다 — 그래서 이건 **자식 요소에 직접 부여**해야 한다.

```css
.item-special {
  align-self: flex-end;   /* 이 아이템만 다른 형제들과 다르게 정렬 */
}
```

## 8. 플렉스박스 속성 역할별 정리

| 역할 | 속성 |
|------|------|
| **배치** | `flex-direction`, `flex-wrap` |
| **공간 분배** | `justify-content`, `align-content` |
| **정렬** | `align-items`, `align-self` |

| 축 | 관련 속성 |
|----|-----------|
| **주축(메인 축)** | `justify-content` |
| **교차축** | `align-items`, `align-content`, `align-self` |

### 메인 축은 "마진"으로도 컨트롤할 수 있다

`margin`을 활용해 메인 축 방향의 간격을 세밀하게 조정할 수도 있다. 예를 들어 `justify-content: space-between` 대신, 특정 아이템에 `margin-left: auto;`를 줘서 **그 아이템만 오른쪽으로 밀어내는 효과**를 만드는 식이다. (`margin: auto`가 남는 공간을 흡수하는 성질을 이용한 관용적 패턴)

## 9. 플렉스 아이템의 크기 관련 속성

### `flex-grow` — 남는 공간을 어떻게 나눠 가질지

컨테이너에 **남는 공간이 있을 때**, 그 공간을 **비율에 따라** 아이템들에게 분배한다.

```css
.item1 { flex-grow: 1; }
.item2 { flex-grow: 2; }   /* item1보다 남는 공간을 2배 더 가져감 */
```

### `flex-shrink` — 공간이 부족할 때 얼마나 줄어들지

컨테이너 공간이 **부족할 때, 아이템이 얼마나 줄어드는지의 비율**을 지정한다.

> **⚠️ 플러터의 Flex(`Expanded`/`flex`)와의 결정적 차이:**
> 플러터의 플렉스(`Expanded`의 `flex` 값)는 **전체 공간을 flex 비율대로 나눠서**, 아이템의 최종 크기가 그 비율 그대로 픽셀 비율로 나온다 (예: flex 1, 2, 3이면 결과 너비도 정확히 1:2:3).
> 반면 CSS의 `flex-grow`/`flex-shrink`는 **전체 공간이 아니라 "남는(또는 부족한) 픽셀만"** 균등하게 쪼개서, 그 비율만큼만 배분한다. 그래서 **아이템의 최종 `width`가 flex 값의 비율 그대로 나오지 않는다** — 이미 각자 가진 기본 크기(`flex-basis` 또는 콘텐츠 크기)가 있고, 그 위에 "여분의 공간"만 비율대로 얹히거나 깎이는 방식이기 때문이다. 플러터처럼 "전체를 비율로 쪼갠다"고 생각하면 예상과 다른 결과가 나올 수 있으니 주의해야 한다.

### `flex-basis` — 아이템의 초기 크기

**플렉스 아이템의 초기 크기 값을 지정**한다. (`flex-grow`/`flex-shrink`가 작동하기 **전**의 기준 크기)

```css
.item {
  flex-basis: 200px;   /* 이 크기를 기준으로, 남는/부족한 공간만큼 grow/shrink가 적용됨 */
}
```

> `flex: <grow> <shrink> <basis>;`처럼 세 값을 한 번에 지정하는 **단축 속성(`flex`)도 존재한다.**

## 10. 반응형 레이아웃 — `flex-wrap` 응용

`flex-wrap`을 `flex-grow` & `flex-basis`와 함께 사용하면, 별도의 미디어 쿼리 없이도 **화면 크기에 따라 자동으로 배치가 바뀌는 반응형 레이아웃**을 만들 수 있다.

```css
.container {
  display: flex;
  flex-wrap: wrap;
}

.item {
  flex-grow: 1;
  flex-basis: 300px;   /* 각 아이템의 기준 너비는 300px */
}
```

- 화면이 넓을 때는 여러 아이템이 한 줄에 나란히 배치되고, 남는 공간은 `flex-grow`로 균등하게 나눠 가진다.
- 창을 줄여서 한 줄에 `flex-basis` 크기(300px)만큼도 안 남으면, `flex-wrap: wrap` 덕분에 **자동으로 다음 줄로 넘어간다.**

> 이 조합이 미디어 쿼리 없이도 "적당히 반응형처럼 보이게" 만드는 실전 패턴이다.

## 11. 마진 상쇄 (Margin Collapsing)

**두 블록 타입 요소의 `margin-top`과 `margin-bottom`이 만나면, 두 값이 더해지는 게 아니라 더 큰 쪽 하나로 결합되는 현상.**

```css
.box1 { margin-bottom: 30px; }
.box2 { margin-top: 20px; }
/* 두 요소가 인접하면, 사이 간격은 30+20=50px이 아니라 더 큰 값인 30px만 적용됨 */
```

### 왜 이런 현상이 있을까?

복잡한 레이아웃에서 **요소 간 간격을 일관되게 유지**할 수 있게 해준다. 만약 마진이 그대로 더해진다면, 요소를 겹겹이 쌓을 때마다 간격이 예상보다 훨씬 벌어지기 쉽다. 마진 상쇄 덕분에 **요소 간 간격을 더 관리하기 쉽고 예측 가능하게** 만들 수 있다.

## 12. 블록/인라인 요소의 수평 중앙 정렬

### 블록 요소의 수평 중앙 정렬

**`margin: auto` 사용.** 블록의 **너비(width)를 지정**하고, **좌우 마진을 `auto`로 설정**한다.

```html
<div class="box margin-auto"></div>
```

```css
.box {
  width: 100px;
  height: 100px;
  background-color: crimson;
  border: 1px solid black;
}

.margin-auto {
  margin: 0 auto;
}
```

> `width`가 지정되어 있어야 좌우에 "남는 공간"이 생기고, 그 남는 공간을 `auto`가 양쪽에 똑같이 나눠 가지면서 가운데 정렬이 된다. (`width`가 없으면 블록은 이미 가로 전체를 차지하므로 `auto`가 나눠 가질 공간 자체가 없다)

### 인라인 요소의 수평 중앙 정렬

**`text-align` 사용.** 단, `text-align`은 요소 자신이 아니라 **부모 요소에 적용**해야 한다.

```html
<div class="text-center">
  <span>inline 요소</span>
</div>
```

```css
.text-center {
  text-align: center;
}
```

> `span` 같은 인라인 요소는 `margin: auto`가 통하지 않는다(인라인은 `width` 자체를 못 씀). 대신 **"이 안의 텍스트/인라인 콘텐츠를 가운데 정렬해라"**는 의미의 `text-align: center`를 **감싸는 부모 블록**에 걸어주는 방식으로 우회한다.

## 13. 종합 정리 — 플렉스박스 속성표

| 속성 | 적용 대상 | 역할 |
|------|-----------|------|
| `display: flex` | 부모(컨테이너) | 플렉스 컨테이너로 지정 |
| `flex-direction` | 부모 | 메인 축의 방향 (row/column 등) |
| `flex-wrap` | 부모 | 줄바꿈 허용 여부 |
| `justify-content` | 부모 | 메인 축 방향 정렬/공간 분배 |
| `align-items` | 부모 | 교차 축 방향, 한 줄 안에서의 정렬 |
| `align-content` | 부모 | 교차 축 방향, 여러 줄 사이의 공간 분배 |
| `align-self` | **자식(개별 아이템)** | 그 아이템만 개별적으로 교차 축 정렬 재정의 |
| `flex-grow` | 자식 | 남는 공간을 가져가는 비율 |
| `flex-shrink` | 자식 | 부족한 공간에서 줄어드는 비율 |
| `flex-basis` | 자식 | 아이템의 초기(기준) 크기 |
| `order` | 자식 | 시각적 배치 순서를 HTML 순서와 무관하게 변경 |
