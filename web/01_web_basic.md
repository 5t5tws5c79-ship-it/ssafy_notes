# 웹 기초 정리 (Web Basic) — HTML & CSS

> **웹 학습 원칙:** 웹 기술을 찾아볼 때는 **MDN(Mozilla Developer Network)**을 기준으로 삼는다. 모질라 재단이 운영하며, 웹 표준 문서로 가장 신뢰할 수 있는 출처다.
> 웹 기술은 굉장히 빠르게 변하므로 **오래된 정보(아웃데이트)에 유의**해야 한다. 검색할 때는 "어떻게 하는지(how to)"보다 **"왜 이렇게 동작하는지(why)"**로 검색하는 습관이 좋다 — 원리를 알면 문법이 바뀌어도 응용할 수 있다.

---

## 1. 웹(Web)이란?

**월드 와이드 웹(World Wide Web)**을 줄여서 웹이라고 부른다.

- 인터넷으로 연결된 컴퓨터들이 정보를 공유하는 **거대한 정보 공간.**
- **웹사이트/웹 애플리케이션**을 통해 사용자들이 정보를 검색하고 상호작용하는 기술.

**웹사이트**는 여러 개의 **웹페이지**가 모인 것으로, 사용자에게 정보나 서비스를 제공하는 공간이다.

### 웹페이지의 구성 요소 — 철골, 페인트, 비헤이비어

| 비유 | 정체 | 역할 |
|------|------|------|
| **철골 (구조)** | **HTML** | 페이지의 뼈대와 의미 |
| **페인트 (스타일)** | **CSS** | 페이지의 디자인과 레이아웃 |
| **비헤이비어 (행동)** | **JS(TS)** | 페이지의 동작과 상호작용 |

> 웹의 구조가 HTML, 웹의 스타일이 CSS다. (JS는 추후 학습 예정)

---

## 2. HTML (HyperText Markup Language)

**웹페이지의 의미와 구조를 정의하는 언어.**

### 하이퍼텍스트(HyperText)란?

웹페이지를 다른 페이지로 연결하는 **링크.**

- 참조를 통해 사용자가 한 문서에서 다른 문서로 **즉시 접근**할 수 있는 **비선형적 상호 연결성.**
- **사용자 주도적 탐색**(링크를 클릭해 원하는 곳으로 자유롭게 이동)을 가능하게 한다.

### HTML은 "마크업 랭귀지"다 — 프로그래밍 언어가 아니다

- HTML은 **데이터의 구조와 의미를 정의**하는 데 집중한다. (예: HTML, 마크다운)
- 조건문·반복문 같은 "로직"을 가진 프로그래밍 언어와는 성격이 다르다.
- 웹 **브라우저가 HTML을 해석해서 화면에 보여준다.**

## 3. HTML의 구조

```html
<!DOCTYPE html>
<html>
  <head>
    <title>페이지 제목</title>
  </head>
  <body>
    페이지에 표시될 내용
  </body>
</html>
```

| 구성 요소 | 역할 |
|-----------|------|
| `<!DOCTYPE html>` | 최상단에 위치. **이 문서가 HTML 문서**라는 걸 나타냄 |
| `<html></html>` | **전체 페이지의 콘텐츠**를 포함하는 최상위 태그 |
| `<head>` | 문서에 대한 **설명·설정**. 컴퓨터(브라우저, 검색엔진)가 식별하는 **메타 정보**. **사용자에게는 보이지 않음** |
| `<title>` | **브라우저 탭**과 **즐겨찾기**에 표시되는 제목으로 사용됨 |
| `<body>` | HTML 문서의 **내용**을 나타냄. **페이지에 실제로 표시되는 모든 콘텐츠**를 작성. **한 문서에 하나의 `<body>`만 존재** |

### 태그의 열고 닫기 규칙

- 태그는 일반적으로 **열고(여는 태그) 닫아야(닫는 태그)** 한다.
- **닫는 태그가 없는 태그도 존재한다.** — 이건 그 태그가 **자체 콘텐츠를 갖지 않고, 태그 자체가 하나의 기능**을 수행하기 때문이다. (예: `<img>`, `<br>`)

---

## 4. HTML 엘리먼트 (요소, Element)

**하나의 요소는 여는 태그 + 닫는 태그 + 안의 내용으로 구성**된다.

```html
<p>My cat is very grumpy</p>
```

- **닫는 태그**는 태그 이름 **앞에 슬래시(`/`)**가 포함된다. (`</p>`)
- 앞서 말했듯, **닫는 태그가 없는 태그**도 있다. (`<img>`, `<input>` 등 — "빈 요소")

---

## 5. HTML 어트리뷰트 (속성, Attribute)

**사용자가 원하는 기준에 맞도록 요소를 설정하거나, 다양한 방식으로 요소의 동작을 조절하기 위한 값.**

### 목적

- 겉으로 나타내고 싶지 않지만 **추가적인 기능·정보를 담고 싶을 때** 사용.
- **CSS에서 스타일을 적용**하기 위해 해당 요소를 **선택하는 값**으로도 활용된다.

### 작성 규칙

1. 속성은 **요소 이름과 속성 사이에 공백**이 있어야 한다.
2. 속성이 **하나 이상**인 경우 속성 사이를 **공백으로 구분**한다.
3. 속성 값은 **열고 닫는 따옴표**로 감싸야 한다.

```html
<p class="editor-note">My cat is very grumpy</p>
```

> 속성값을 감싸는 따옴표는 **작은따옴표든 큰따옴표든** 가능하지만, **큰따옴표를 권장**한다.

---

## 6. 대표적인 태그

### `<a>` (앵커, 링크) / `<p>` (문단)

- IDE(VS Code 등)에서 `!`를 치면 HTML 기본 구조를 **자동완성**해준다.
- `<a>` 태그를 자동완성하면 `href="#"`처럼 빈 값이 생기는데, **비어있는 값도 중요한 속성**이니 반드시 실제 값으로 채워야 한다.

> **재밌는 사실:** 웹에서 보이는 화려한 버튼들도, 겉모습은 CSS로 꾸며놨을 뿐 **기능 자체는 대부분 `<a>` 태그**인 경우가 많다. (클릭하면 다른 페이지로 이동하는 것 = 하이퍼텍스트 링크)

### `<img>` (이미지)

```html
<img src="cat.jpg" alt="grumpy cat sitting on a couch">
```

| 속성 | 역할 |
|------|------|
| `src` | 이미지 파일의 **경로(source)** |
| `alt` | 이미지를 못 보여줄 때 표시되는 **대체 텍스트(alternative text)**. 스크린 리더가 시각장애인에게 읽어주는 내용이기도 함 |

## 7. 텍스트 구조 (Text Structure)

**텍스트의 구조와 의미를 제공**하는 태그들.

- `<h1>` 같은 헤딩 태그는 **단순히 글씨를 크게 만드는 게 아니라**, "이 텍스트가 현재 문서의 **최상위 제목**이다"라는 **의미를 부여**하는 것이다.
- 의미에 맞는 태그를 쓰는 것은 **스크린 리더 접근성**과 **검색 엔진 최적화(SEO)**의 기본이 된다.

### 대표적인 텍스트 구조 태그

| 태그 | 의미 |
|------|------|
| `<h1>` ~ `<h6>` | 제목(heading). 숫자가 작을수록 더 상위 제목 |
| `<p>` | 문단(paragraph) |
| `<ol>`, `<ul>`, `<li>` | 리스트(순서 있는/없는 목록, 목록 항목) |
| `<em>` | 강조(기울임, 의미상 강조) |
| `<strong>` | 중요함(굵게, 의미상 중요도가 더 강함) |

> **태그는 외우지 말고, 필요할 때마다 찾아서 쓰는 것을 권장한다.** HTML 태그 종류는 굉장히 많아서 전부 암기하는 건 비효율적이다.

## 8. 웹 스타일링 — CSS (Cascading Style Sheets)

**"캐스케이딩(Cascading, 계단식으로 흐르는)"** 스타일 시트.

### 스타일 적용 방법 3가지

| 방법 | 설명 |
|------|------|
| **인라인 스타일 (Inline)** | HTML 요소 안에 `style` **속성 값**으로 직접 작성 |
| **인터널 스타일 시트 (Internal)** | `<head>` 태그 안에 `<style>` 태그를 작성하고 그 안에 CSS 작성 |
| **엑스터널 스타일 시트 (External)** | 별도의 `.css` 파일을 만들고, HTML에서 `<link>` 태그로 불러오기 |

```html
<!-- 인라인 -->
<p style="color: red;">Hello</p>

<!-- 인터널 -->
<head>
  <style>
    p { color: red; }
  </style>
</head>

<!-- 엑스터널 -->
<head>
  <link rel="stylesheet" href="style.css">
</head>
```

### 적용 우선순위

**인라인 > 인터널 > 엑스터널** 순으로 적용된다.

> **인라인 스타일은 지양하는 것을 권장한다.** 재사용이 어렵고 유지보수를 방해하기 때문에, **테스트나 아주 특수한 경우**에만 제한적으로 사용하자.

---

## 9. CSS 구문 (Syntax)

```css
선택자 {
  속성: 값;
}
```

| 구성 요소 | 설명 |
|-----------|------|
| **선택자 (Selector)** | **누구를 꾸밀지** 지정하는 부분. **아주 중요** |
| **선언 (Declaration)** | 어떻게 꾸밀지에 대한 **구체적인 한 줄 명령**. `속성: 값;` 형태로, **세미콜론(`;`)**으로 끝남 |
| **속성 (Property)** | 바꾸고 싶은 **스타일의 종류** (예: `color`, `width`) |
| **값 (Value)** | 그 속성에 적용할 **구체적인 설정** (예: `red`, `200px`) |

---

## 10. CSS 선택자 (Selector)

### 기본 선택자

| 선택자 | 문법 | 설명 |
|--------|------|------|
| **전체 선택자** | `*` | **모든 요소**를 선택 |
| **요소 선택자** | `p`, `div` | 지정한 **모든 태그**를 선택 |
| **클래스 선택자** | `.클래스명` | 주어진 **클래스 속성을 가진 모든 요소**를 선택 → **재사용성**이 핵심 |
| **아이디 선택자** | `#아이디명` | **아이디 속성을 가진 요소**를 선택 |

> **아이디 선택자의 특징:** 이 스타일은 **문서 전체에서, 주어진 아이디를 가진 요소가 단 하나만 있어야 한다.** 즉, "유일한 스타일 하나를 만들고 딱 한 곳에서만 쓴다"는 용도에 맞다.

> **실무 감각:** 실제로 쓰이는 선택자의 **90%는 클래스 선택자**다. 재사용 가능하고 유연하기 때문.

### 결합자 (Combinator) — 자손 결합자

**첫 번째 요소의 하위(자손) 요소를 선택**하는 방식.

```css
div p {
  color: blue;
}
```

> `div` 안에 있는 모든 `p` 요소를 선택한다. (직계 자식만 원하면 `>`를 쓰는 **자식 결합자**를 사용 — `div > p`)

## 11. 명시도 (Specificity)

**결과적으로 요소에 어떤 CSS 선언이 적용될지 결정하기 위한 알고리즘.**

- 명시도는 **선택자들의 "점수 싸움"**이다.
- 각 선택자에 **가중치를 계산**해서, 어떤 스타일을 적용할지 결정한다.

### 명시도 우선순위 (높은 순)
```
!important > 인라인 스타일 > id 선택자 > 클래스 선택자 > 요소 선택자
```

### 규칙 정리

1. **선택자 종류가 다르면** → 더 구체적인(강한) 선택자가 이긴다. (클래스 선택자 vs 요소 선택자가 붙으면 **클래스 선택자가 이김**)
2. **동일한 우선순위라면** → **마지막에 선언된 것**이 사용된다.

```css
h1 { color: red; }
h1 { color: purple; }
/* 결과: purple  (동일한 명시도 → 나중에 선언된 것 승리) */
```

```css
.make-red { color: red; }
h1 { color: purple; }
/* h1 태그에 class="make-red"가 붙어있어도... */
/* 결과: red  (클래스 선택자가 요소 선택자보다 명시도가 높음) */
```

> **⚠️ 핵심 주의:** 마지막 예시처럼 **동일한 우선순위 규칙("나중에 선언된 게 이김")은 명시도가 같을 때만** 적용된다. **호출부(코드에서 어디 쓰였는지)는 중요하지 않고, CSS가 "선언된 순서"로 비교**한다는 점이 핵심이다.

### `!important` — 명시도를 강제로 뒤집는 방법

```css
p {
  color: blue !important;   /* 다른 어떤 선택자도 이걸 이길 수 없음 */
}
```

> `!important`를 주면 **아무도 못 이긴다.** 다만 이건 **캐스케이딩(계단식 우선순위)의 구조를 무시하고 강제로 스타일을 적용**하는 방식이므로, **사용을 권장하지 않는다.** 디버깅을 어렵게 만드는 대표적인 원인이 된다.

## 12. CSS의 선언 (Declaration)

선택된 요소에 적용할 스타일을 **구체적으로 명시**하는 부분.

- **프로퍼티(속성)와 값**은 CSS가 **미리 정의해둔 키워드**를 사용해야 한다. (아무 이름이나 쓸 수 있는 게 아니라, `color`, `width` 같은 정해진 속성명이 있음)

---

## 13. 값의 단위 (Units)

| 분류 | 단위 | 특징 |
|------|------|------|
| **절대 단위** | `px`, `pt`, `cm` 등 | 다른 요소의 영향을 받지 않는 **고정된 크기** |
| **상대 단위** | `%`, `em`, `rem`, `vw`, `vh` 등 | **다른 요소(부모 등)의 크기에 따라 상대적으로 결정** |

### `px` — 픽셀, 대표적인 절대 단위

- 화면을 구성하는 가장 작은 단위인 **픽셀을 기준**으로 하는 절대 단위.
- 모니터 해상도에 따라 크기가 결정되며, **직관적이고 예측이 쉽다.**
- **단점:** 브라우저의 기본 폰트 크기를 사용자가 변경해도 **요소 크기가 함께 조절되지 않아** 접근성이 떨어진다. **반응형에 불리하다.**

### `em` — 부모 기준 상대 단위

**부모 요소의 폰트 사이즈를 기준**으로 크기가 결정되는 상대 단위.

- 만약 부모 요소에 폰트 사이즈가 없다면, **상위의 폰트 사이즈를 상속**받는다.
- **문제점:** 부모가 또 다른 부모의 `em`을 물려받는 식으로 **중첩적으로 상대 단위가 쌓이면**, 크기가 계속 변하면서 **계산이 복잡해지고 예측이 어려워진다.**

```html
<div class="parent-for-em">     <!-- font-size: 20px -->
  부모 요소
  <div class="em-unit">          <!-- font-size: 1.5em -->
    em 단위 자식 (1.5em ⇒ 20 × 1.5 = 30px)
  </div>
</div>
```

### `rem` (Root EM) — em의 단점을 해결

`em`의 단점(중첩되면 예측 어려움)을 극복하기 위해 등장.

- **최상위 요소(`<html>`)의 폰트 크기**(대부분 브라우저 기본값 **16px**)를 기준으로 크기가 결정된다.
- 부모가 몇 겹으로 중첩돼 있든 **항상 `<html>` 하나만 기준으로 삼으므로** 예측이 쉽다.

```css
.rem-unit {
  font-size: 1.5rem;   /* 16px × 1.5 = 24px (부모와 무관하게 항상 이 값) */
}
```

> **한 줄 비유:** em은 **"부모를 따를 것인가"**, rem은 **"뿌리를 지킬 것인가"**. em은 부모가 커지면 나도 커지는 **가변적**인 성질, rem은 부모가 누구든 나는 내 길을 가는 **고정적**인 성질.

### `%` — 부모의 크기 대비 몇 퍼센트

`em`, `rem`이 **"글자 크기"**를 기준 삼는다면, `%`는 **"부모의 크기(영역)"**를 기준으로 삼는다.

```css
.child-percent {
  width: 50%;   /* 부모의 width가 400px이면 → 200px */
}
```

> **비유:** em·rem이 "글씨를 몇 배로 키울까"였다면, `%`는 "부모가 가진 공간을 몇 퍼센트 차지할까"이다. 방 하나를 두 사람이 반씩 나눠 쓰는 것과 같아서, 방이 커지면 각자의 몫도 함께 커진다.

### ⚠️ `%`를 어렵게 만드는 함정 — 속성마다 "무엇의 %"인지가 다르다

| 속성 | 무엇의 %인가 |
|------|--------------|
| `width` | 부모의 **가로 크기** |
| `height` | 부모의 **세로 크기** (⚠️ 부모의 높이가 명시적으로 정해져 있어야 동작함) |
| `font-size` | 부모의 **글자 크기** (`em`과 사실상 동일) |
| `padding` / `margin` | **상하좌우 모두** 부모의 **가로 크기** 기준 (세로 방향 padding/margin도 부모의 width를 기준으로 계산됨 — 흔히 헷갈리는 부분) |

### 단위 비교 총정리

| 단위 | 기준 | 장점 | 단점/주의사항 | 추천 사용처 |
|------|------|------|----------------|--------------|
| `px` | 화면의 픽셀 | 직관적, 고정된 크기 | 접근성/반응형에 불리 | `border-width` 등 절대적 크기가 필요할 때 |
| `em` | 부모 요소의 font-size | 부모에 따라 유연하게 변경 | 중첩 시 계산 복잡 | 특정 컴포넌트 내부에서만 상대적 크기 조절이 필요할 때 |
| `rem` | `<html>`의 font-size | 일관성, 유지보수성, 접근성 | 루트 폰트 크기에 의존적 | 웹사이트 전반의 font-size, margin, padding 등 |
| `%` | 부모 요소의 크기 | 컨테이너에 맞춰 유동적으로 | 속성마다 기준이 다름. 특히 height는 부모 높이가 정해져야 동작 | width, height 등 레이아웃 구성 시 |

> **TIP:** 웹 디자인에서는 반응형 웹과 접근성 때문에 **"상대 단위의 중요성"**이 매우 높다. 값이 0일 때는 단위를 생략하는 것이 권장된다. (`margin: 0;`처럼)

### 💡 플러터(Flutter) 개발자를 위한 비교

플러터를 몰라도 이해할 수 있게 개념 위주로 짧게 짚어본다.

- **`px`에 가장 가까운 것:** 플러터에서 위젯 크기를 `width: 200`처럼 **숫자로 직접 고정**하는 방식. 다만 플러터의 숫자는 이미 **논리적 픽셀(logical pixel)**이라, 기기 해상도(DPI)와 무관하게 어느 정도 자동으로 맞춰진다는 점에서 CSS의 순수 `px`보다는 조금 더 "안전한" 고정 크기에 가깝다.
- **`%`에 가장 가까운 것:** 플러터의 `FractionallySizedBox`(`widthFactor: 0.5`처럼 부모의 몇 %를 차지할지 지정) 또는 `Row`/`Column`의 `Expanded`, `Flexible`(비율로 공간을 나눠 가짐)이 CSS `%`가 하려는 것과 목적이 같다 — **"부모 공간을 기준으로 상대적인 크기"**를 정하는 것.
- **`em`/`rem`에 딱 맞는 개념은 없다.** 가장 비슷한 것을 찾자면, 플러터에는 **`MediaQuery`의 `textScaleFactor`**(사용자의 기기 접근성 설정에 따라 앱 전체 텍스트 크기가 일괄적으로 커지고 작아지는 값)가 있는데, 이건 "루트(기기 설정) 하나를 기준으로 전체가 함께 커진다"는 점에서 `rem`의 "하나의 기준점을 두고 일관되게 관리한다"는 철학과 정신은 닮았다. 다만 CSS처럼 `1.5em`, `2rem`처럼 요소마다 배수를 직접 지정하는 문법 자체는 플러터에 없다.
- **가장 큰 차이:** CSS는 **"단위 시스템 자체가 상대/절대로 나뉘어 있고, 브라우저가 매번 계산**"해주지만, 플러터는 기본적으로 **모든 크기를 숫자(논리적 픽셀)로 다루고**, "부모에 비례한 크기"가 필요하면 `Expanded`, `FractionallySizedBox`, `LayoutBuilder` 같은 **위젯(도구)을 명시적으로 골라 써야** 한다. 즉 CSS는 "단위를 바꿔서" 상대성을 표현하고, 플러터는 "위젯을 바꿔서" 상대성을 표현한다고 보면 된다.

## 14. CSS 박스 모델 (Box Model)

**웹페이지의 모든 HTML 요소를 감싸는 사각형 상자 모델.**

> **CSS 입장에서 모든 요소는 사각형이다.** 아무리 둥근 버튼이라도, CSS 레이아웃 계산 관점에서는 결국 사각형 박스로 다뤄진다.

박스는 **내용(content), 안쪽 여백(padding), 테두리(border), 외부 간격(margin)**으로 구성되어, 요소의 **크기와 배치**를 결정한다.

### 박스 구성의 방향별 속성값

바깥에서 안쪽으로: **margin → border → padding → content**
```
margin-top
border-top
padding-top
┌─────────────┐
│ height │
│ width │
└─────────────┘
padding-bottom
border-bottom
margin-bottom
```

- 각 레이어마다 `-top`, `-right`, `-bottom`, `-left` 네 방향의 속성이 있다. (예: `margin-left`, `border-right`, `padding-top` 등)
- **content**의 크기는 `width`, `height`로 정한다.

### 박스 구성 요소 예시

```html
<body>
  <div class="box1">box1</div>
  <div class="box2">box2</div>
</body>
```

```css
.box1 {
  width: 200px;
  padding-left: 25px;
  padding-bottom: 25px;
  margin-left: 25px;
  margin-top: 50px;
  border-width: 3px;
  border-style: solid;
  border-color: black;
}

.box2 {
  width: 200px;
  padding: 25px 50px;    /* 단축 속성 */
  margin: 25px auto;      /* 단축 속성 — auto는 수평 가운데 정렬 */
  border: 1px dashed black;  /* 보더 단축 속성 */
}
```

> `box2`에서 `margin: 25px auto;`의 `auto`는 **좌우 여백을 자동으로 맞춰 수평 가운데 정렬**시키는 관용적인 패턴이다.

## 15. Shorthand 속성 (단축 속성)

여러 개의 세부 속성을 **한 줄로 줄여 쓸 수 있는** 속성.

### `border` 단축 속성

`border-width`, `border-style`, `border-color`를 **한 번에 설정**하기 위한 속성.

```css
/* 작성 순서는 영향을 주지 않음 */
border: 2px solid black;
```

### `margin` & `padding` 단축 속성

**4방향의 속성을 각각 지정하지 않고 한 번에** 지정할 수 있는 속성. **값의 개수**에 따라 적용되는 방향이 달라진다.

| 값 개수 | 적용 순서 | 예시 |
|:-------:|-----------|------|
| **4개** | 상 / 우 / 하 / 좌 (시계방향) | `margin: 10px 20px 30px 40px;` |
| **3개** | 상 / 좌우 / 하 | `margin: 10px 20px 30px;` |
| **2개** | 상하 / 좌우 | `margin: 10px 20px;` |
| **1개** | 공통(4방향 모두 동일) | `margin: 10px;` |

```css
/* 4개 - 상우하좌 */
margin: 10px 20px 30px 40px;
padding: 10px 20px 30px 40px;

/* 3개 - 상/좌우/하 */
margin: 10px 20px 30px;
padding: 10px 20px 30px;

/* 2개 - 상하/좌우 */
margin: 10px 20px;
padding: 10px 20px;

/* 1개 - 공통 */
margin: 10px;
padding: 10px;
```

## 16. Box Sizing — 표준 상자 모델 vs 대체 상자 모델

### 표준 상자 모델 (`content-box`) — 기본값

- `width`, `height`로 지정한 크기는 **오직 content 영역**의 크기다.
- 여기에 **padding과 border가 추가로 더해져서** 실제로 화면에 차지하는 크기가 늘어난다.

```css
.box {
  width: 100px;
  padding: 20px;
  border: 5px solid black;
  /* 실제 화면 차지 너비 = 100 + 20*2 + 5*2 = 150px */
}
```

### 대체 상자 모델 (`border-box`)

- `width`, `height`가 **테두리(border)까지 포함한 전체 크기**를 의미하게 된다.
- 즉 `width: 100px`이면, padding과 border를 더해도 실제 상자 너비는 **항상 100px로 고정**된다. (그 안에서 content 영역이 자동으로 줄어들어 맞춰짐)

```css
.box {
  box-sizing: border-box;
  width: 100px;
  padding: 20px;
  border: 5px solid black;
  /* 실제 화면 차지 너비 = 항상 100px (border 기준) */
}
```

### 왜 `border-box`가 더 편할까?

> **"사람은 보더(border-box) 기준이 더 편하다."**
> 표준 모델(`content-box`)은 padding·border를 추가할 때마다 **전체 크기가 매번 달라져서** 레이아웃을 예측하기 어렵다. `border-box`는 **내가 지정한 `width`/`height` 값이 곧 실제 화면에서 차지하는 크기**가 되므로, 레이아웃을 계산하고 조정하기 훨씬 쉽다.

### 실무 관행 — 전체 선택자로 미리 바꿔두기

```css
* {
  box-sizing: border-box;
}
```

> 많은 개발자들이 프로젝트 시작 시 **전체 선택자(`*`)로 `box-sizing: border-box`를 미리 적용**해두고 작업을 시작한다. 이렇게 바꿔두면, `width`와 `height` 값을 **테두리 기준으로 딱 그 픽셀만큼** 잡아주기 때문에 레이아웃 조정이 훨씬 용이해진다.
