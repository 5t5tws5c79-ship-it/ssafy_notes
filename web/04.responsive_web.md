# 반응형 웹(Responsive Web)과 UX/UI, Bootstrap Grid System

## 1. 반응형 웹이 필요한 이유

**각 기기마다 화면 크기가 똑같다는 보장은 없다.**

- 큰 화면(데스크탑)만 대응해서 만든 페이지가 작은 화면(모바일)으로 가면 레이아웃이 깨지고 이상해진다.
- 사용자는 **깨진 화면에서는 곧바로 떠난다.** (이탈)

### 반응형 웹이란?

**디바이스 종류나 화면 크기에 상관없이, 일관된 레이아웃과 사용자 경험을 제공하는 디자인 기술.**

> 반응형 웹은 결국 **좋은 UX를 만들기 위한 기술**이다.

---

## 2. UX와 UI

| 용어 | 정의 |
|------|------|
| **UX (User eXperience)** | 사용자가 서비스를 이용하며 느끼는 **만족감이자 경험** |
| **UI (User Interface)** | 사용자가 서비스와 **만나는 화면의 디자인과 배치** |

**UX란?** 제품이나 서비스를 사용하는 사람들이 느끼는 **전체적인 경험과 만족도를 개선하고 최적화**하는 것.

### UX의 세 가지 경험 유형

| 유형 | 예시 |
|------|------|
| **감각적 경험** | 러쉬(LUSH) 매장 근처만 가도 느껴지는 **특유의 향기** |
| **기능적 경험** | 음악 앱에 대충 입력해도 **찰떡같이 원하는 곡을 찾아주는** 스마트한 검색 결과 |
| **편의적 경험** | 바쁜 아침, 모바일 오더를 통해 줄 서는 과정 없이 매장에 도착하자마자 커피를 픽업하는 **매끄러운 경험** |

## 5. 좋은 UI란 무엇인가

**예쁜 건 당연한 것이고**, 진짜 좋은 UI는 다음을 해낸다:

- **정보의 위계를 잡아** 사용자가 **무엇을 먼저 봐야 할지 유도**하는 것.
- **일관성을 통해 학습 비용을 줄이는 것.** (한 번 배운 조작 방식이 다른 화면에서도 통해야 사용자가 매번 새로 배우지 않아도 됨)

### UI의 주요 요소

- **레이아웃 그리드**
- **타이포그래피 & 컬러**
- **인터랙션 요소**

### 필요 도구 및 산출물

- **와이어프레임**
- **디자인 시스템**
- **프로토타입**

## 6. 실무에서의 UX/UI 직무 (참고)

| 회사 | UX (User/UX Researcher) | UI (Product/Interaction Designer) |
|------|--------------------------|-------------------------------------|
| **구글** | 사용자의 경험을 이해하기 위한 **통계 모델을 설계** | 다양한 **디자인 프로토타이핑 툴**을 사용해서 개발 가이드를 제공 |
| **MS** | 리서치를 기획하고 **사용자에 대한 지표를 정의** | **시각 디자인**을 고려해서 체계적인 디자인 컨셉을 보여줌 |
| **Meta** | **정성적/정량적 방법**을 사용해서 사용자 조사를 실시 | 제품을 이해하고 더 나은 **UI Flow**와 사용자 경험을 디자인 |

> 회사마다 표현은 다르지만, 공통적으로 **UX는 "이해·조사·지표 정의"**, **UI는 "설계·프로토타입·비주얼 완성"**에 초점이 맞춰져 있음을 알 수 있다.

## 7. 희망 보행로 (Desire Path)

> **"사용자의 실제 행동 패턴을 무시한 디자인은 결국 외면받거나, 짓밟힌 잔디처럼 망가진 결과를 낳게 된다."**

공원에 정해진 포장도로가 있어도, 사람들이 실제로 다니기 편한 길로 지름길을 만들면 결국 그 위의 잔디가 밟혀 죽고 새로운 길이 생긴다 — 이것이 "희망 보행로(desire path)"다. UX/UI 설계도 마찬가지로, **디자이너가 의도한 경로가 아니라 사용자가 실제로 원하는 경로를 관찰하고 반영**해야 한다는 비유다.

## 8. Bootstrap 그리드 시스템 (Grid System)

### 순수 CSS로 반응형을 구현하려면?

우리가 배운 CSS만으로 반응형 레이아웃을 구현하려면 어떻게 해야 할까?

- 일일이 **너비를 계산**하고, **미디어 쿼리로 분기점(breakpoint)을 직접 나눠야** 할까?

**Bootstrap이 어느 정도 기준점을 미리 잡아줬다.**

### 그리드 시스템이란?

**웹 페이지의 레이아웃을 조정하는 데 사용되는, 12개의 컬럼으로 구성된 시스템.**

- **왜 하필 12일까?** → **약수가 적당히 많아서.** (12는 1, 2, 3, 4, 6, 12로 나누어떨어짐 — 2등분, 3등분, 4등분, 6등분 등 다양한 분할이 딱 맞아떨어진다)
- **내부 요소도 12칸으로 나눠서** 활용한다. (중첩된 grid도 다시 12칸 기준)

### 그리드 시스템의 구성 요소

| 용어 | 역할 |
|------|------|
| **컨테이너 (Container)** | 컬럼들을 담고 있는 공간. **바깥쪽 마진**을 가짐 |
| **로우 (Row)** | 컨테이너 클래스 안에 존재하는 **행** 단위. 12개의 컬럼을 구성하며 다음 줄로 넘어감 |
| **컬럼 (Column)** | 실제 콘텐츠가 들어가는 칸. 12칸 중 몇 칸을 차지할지 지정 |
| **거터 (Gutter)** | 컬럼 사이의 **여백(공간)** |

```html
<div class="container">
  <div class="row">
    <div class="col-4"></div>
    <div class="col-4"></div>
    <div class="col-4"></div>
  </div>
</div>
```

> 각각의 `div`에게 **4칸씩** 주었고, 총합 12칸 안에서 움직이게 된다.

## 9. Bootstrap 그리드 실습 예시

### Basic — 기본 사용법

```html
<h2 class="text-center">Basic</h2>
<div class="container">
  <div class="row">
    <div class="col">
      <div class="box">col</div>
    </div>
    <div class="col">
      <div class="box">col</div>
    </div>
    <div class="col">
      <div class="box">col</div>
    </div>
  </div>

  <div class="row">
    <div class="col-4">
      <div class="box">col-4</div>
    </div>
    <div class="col-4">
      <div class="box">col-4</div>
    </div>
    <div class="col-4">
      <div class="box">col-4</div>
    </div>
  </div>

  <div class="row">
    <div class="col-2">
      <div class="box">col-2</div>
    </div>
    <div class="col-8">
      <div class="box">col-8</div>
    </div>
    <div class="col-2">
      <div class="box">col-2</div>
    </div>
  </div>
</div>
```

- `.col`만 쓰면 **남은 공간을 균등하게 나눠 가진다.**
- `.col-4`처럼 숫자를 지정하면 **12칸 중 정확히 그만큼**을 차지한다. (`col-4` × 3 = 12칸 꽉 채움)
- `col-2` + `col-8` + `col-2`처럼 **합이 12만 맞으면** 자유롭게 배분 가능하다.

### Nesting — 중첩

```html
<div class="row">
  <div class="box col-4">col-4</div>
  <div class="box col-8">
    <div class="row">
      <div class="col-6"><div class="box">col-6</div></div>
      <div class="col-6"><div class="box">col-6</div></div>
      <div class="col-6"><div class="box">col-6</div></div>
      <div class="col-6"><div class="box">col-6</div></div>
    </div>
  </div>
</div>
```

> `col-8` 안에 **새로운 `row`를 다시 만들면**, 그 안에서는 **다시 12칸 기준으로 새롭게 나뉜다.** (바깥의 8칸이 안쪽에서는 새로운 12칸으로 재해석됨 — "내부 요소도 12칸으로 나눠서 활용"한다는 게 바로 이 뜻)

### Offset — 밀어내기

```html
<div class="row">
  <div class="col-4"><div class="box">col-4</div></div>
  <div class="col-4 offset-4"><div class="box">col-4 offset-4</div></div>
</div>
<div class="row">
  <div class="col-3 offset-3"><div class="box">col-3 offset-3</div></div>
  <div class="col-3 offset-3"><div class="box">col-3 offset-3</div></div>
</div>
<div class="row">
  <div class="col-6 offset-3"><div class="box">col-6 offset-3</div></div>
</div>
```

- **`offset-N`**은 해당 컬럼 앞에 **N칸만큼의 빈 공간**을 만들어 밀어낸다.
- `col-6 offset-3`은 (3칸 비우고) + (6칸 채우고) + (나머지 3칸 비움) = **가운데 정렬된 효과**를 만든다.

### Gutters — 컬럼 사이 간격 조절

```html
<!-- gx-0: 좌우(가로) 거터 제거 -->
<div class="row gx-0">
  <div class="col-6"><div class="box">col</div></div>
  <div class="col-6"><div class="box">col</div></div>
</div>

<!-- gy-5: 위아래(세로) 거터 확대 -->
<div class="row gy-5">
  <div class="col-6"><div class="box">col</div></div>
  <div class="col-6"><div class="box">col</div></div>
  <div class="col-6"><div class="box">col</div></div>
  <div class="col-6"><div class="box">col</div></div>
</div>

<!-- g-5: 상하좌우 거터 모두 확대 -->
<div class="row g-5">
  <div class="col-6"><div class="box">col</div></div>
  <div class="col-6"><div class="box">col</div></div>
  <div class="col-6"><div class="box">col</div></div>
  <div class="col-6"><div class="box">col</div></div>
</div>
```

| 클래스 | 의미 |
|--------|------|
| `gx-N` | **가로(x축)** 거터 크기 |
| `gy-N` | **세로(y축)** 거터 크기 |
| `g-N` | **가로+세로 모두** 거터 크기 |

### 거터(Gutter)의 동작 원리 — 중요

**그리드 시스템에서 컬럼 사이에 있는 여백 영역이 거터다.**

- 실제 **컬럼 간의 좌우 간격 자체는 변하지 않는다.** 대신 **패딩(padding)으로 인해 컬럼 안 콘텐츠의 너비가 변한다.**
- **위아래(세로) 거터는 마진(margin)**으로 밀어낸다.

> **왜 좌우는 패딩으로, 세로는 마진으로 처리할까?**
> **12칸이라는 "국룰"(고정 규칙)** 때문이다. 만약 좌우 거터를 마진으로 처리하면, 실제로 컬럼을 밀어내는 셈이 되어 **전체 너비 합이 12칸을 벗어나게 된다.** 그래서 컬럼의 **바깥 경계(12칸 기준 너비)는 그대로 유지**하면서, 그 **안쪽에서만 패딩으로 여백을 만들어** 시각적으로 간격이 있어 보이게 처리한다. 반면 세로 방향은 애초에 "12칸 안에서 맞춰야 하는" 제약이 없으므로, 자유롭게 마진으로 밀어낼 수 있다.

## 10. Breakpoints (반응형 분기점)

**그리드 시스템 = "칸 수 나누기" 게임 + "화면 크기마다 칸 수를 다르게 나누기" 게임.**

**Breakpoints란?** 웹 페이지를 다양한 화면 크기에서 적절하게 배치하기 위한 **분기점.**

- **화면 너비에 따라 6개의 분기점을 제공**한다: `xs`, `sm`, `md`, `lg`, `xl`, `xxl`
- (참고: `xxl`은 원래 Bootstrap에 없었는데 **나중에 추가되었다.**)

### Breakpoints 상세 표

| | **xs** | **sm** | **md** | **lg** | **xl** | **xxl** |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| **화면 너비** | `<576px` | `≥576px` | `≥768px` | `≥992px` | `≥1200px` | `≥1400px` |
| **Container max-width** | None (auto) | 540px | 720px | 960px | 1140px | 1320px |
| **Class prefix** | `.col-` | `.col-sm-` | `.col-md-` | `.col-lg-` | `.col-xl-` | `.col-xxl-` |

### 클래스 이름 읽는 법

- `col-` (접두사 없음) → **`xs` 기준**, 즉 **모든 화면 크기의 기본값**
- `col-sm-4` → **`sm` 사이즈부터** 4칸
- `col-xl-3` → **`xl` 사이즈(라지 사이즈) 이상부터** 3칸으로 표현 가능

> **핵심 규칙 — "이상으로" 적용된다:** 예를 들어 `col-xl-3`이라고 지정했는데, `xxl`에 대한 별도 지정이 없다면? **더 큰 breakpoint에 대한 별도 강조점이 없으면, 그 지점(`xl`) 이상으로는 전부 그 값이 그대로 작동한다.** 즉 breakpoint 값은 "딱 그 구간에서만" 적용되는 게 아니라 **"그 이상 전체"에 적용**된다는 점이 핵심이다.

### Breakpoints 실습 예시

```html
<h2 class="text-center">Breakpoints</h2>
<div class="container">
  <div class="row">
    <div class="col-12 col-sm-6 col-md-1  col-xl-4">
      <div class="box">col</div>
    </div>
    <div class="col-12 col-sm-6 col-md-10 col-xl-4">
      <div class="box">col</div>
    </div>
    <div class="col-12 col-sm-6 col-md-1 col-xl-4">
      <div class="box">col</div>
    </div>
    <div class="col-12 col-sm-6 col-md-12 col-xl-12">
      <div class="box">col</div>
    </div>
  </div>
</div>
```

> 화면 크기에 따라 같은 요소가 **`xs`일 땐 12칸(한 줄 전체)**, **`sm`일 땐 6칸(두 칸씩)**, **`md`일 땐 1/10/1/12칸**, **`xl`일 땐 4/4/4/12칸**으로 각각 다르게 배치된다. 이게 바로 하나의 HTML로 여러 화면 크기에 대응하는 반응형의 핵심이다.

### Breakpoints + Offset 조합

```html
<div class="row g-4">
  <div class="col-12 col-sm-4 col-md-6">
    <div class="box">col</div>
  </div>
  <div class="col-12 col-sm-4 col-md-6">
    <div class="box">col</div>
  </div>
  <div class="col-12 col-sm-4 col-md-6">
    <div class="box">col</div>
  </div>
  <div class="col-12 col-sm-4 offset-sm-4 col-md-6 offset-md-0">
    <div class="box">col</div>
  </div>
</div>
```

> **⚠️ 주의할 부분:** `offset-sm-4 ... offset-md-0`처럼, **작은 화면(`sm`)에서 준 오프셋을 큰 화면(`md`)에서 다시 `0`으로 "리셋"**해줘야 하는 경우가 있다. Breakpoint는 "그 이상 전체에 적용"되는 특성이 있으므로, `sm`에서 준 `offset-sm-4`를 `md`에서 명시적으로 해제(`offset-md-0`)하지 않으면 **의도치 않게 `md` 이상에서도 오프셋이 계속 유지**된다. 이 점을 놓치면 큰 화면에서 레이아웃이 예상과 다르게 밀려 보이는 버그가 생기기 쉽다.

## 12. CSS 레이아웃 기술들의 상호보완 관계

CSS 레이아웃 기술들(그리드 시스템, 플렉스박스 등)은 **각각 고유한 특성과 장단점**을 가지고 있다. 이들은 **서로 배타적인 것이 아니라 상호보완적**이며, 상황에 따라 **적합한 도구가 달라진다.**

> **비유:** **"숲은 그리드로 잡고, 나무는 플렉스박스로 섬세하게 다듬는다."**
> 전체 페이지의 큰 골격(레이아웃)은 Bootstrap 그리드 시스템으로 잡고, 그 안의 개별 컴포넌트(카드 내부의 아이콘+텍스트 정렬 등) 같은 **세부적인 배치**는 Flexbox로 다듬는 식으로 **함께 사용하는 것이 실전 패턴**이다.

## 13. Grid Cards — `row-cols`

**`row-cols` 클래스**를 사용하면 **행(row)당 표시할 열(column) 수를 손쉽게 제어**할 수 있다.

```html
<h2 class="text-center">Grid Cards</h2>
<div class="container">
  <div class="row row-cols-1 row-cols-md-2">
    <div class="col">
      <div class="card">
        <div class="card-body">
          <h5 class="card-title">Card title</h5>
          <p class="card-text">This is a longer card with supporting text...</p>
        </div>
      </div>
    </div>
    <!-- 카드가 4개 더 반복됨 -->
  </div>
</div>
```

- `row-cols-1` → 기본(작은 화면)에서는 **한 행에 카드 1개.**
- `row-cols-md-2` → `md` 사이즈 이상에서는 **한 행에 카드 2개.**

> **핵심 차이:** 앞서 배운 `col-6`, `col-4` 같은 방식은 **"각 컬럼이 몇 칸을 차지하는가"**를 직접 지정하는 방식이다. 반면 `row-cols-N`은 **"한 행에 몇 개(N개)의 아이템을 넣을지"**를 지정하면, Bootstrap이 알아서 12칸을 그 개수만큼 균등 분할해준다. **카드처럼 개수가 명확한 반복 콘텐츠**를 다룰 때 훨씬 간결하다.
