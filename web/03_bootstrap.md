# Bootstrap & CSS 방법론 정리

## 1. 왜 Bootstrap이 필요한가?

CSS를 사용하다 보면 **반복되는 작업이 너무 많다.**

- 자주 사용되는 **글자 크기, 색상, 간격** 등을 매번 새로 정의하는 건 비효율적이다.
- 이런 값들을 **미리 잘 만들어두고 제공하는 서비스**가 필요하다.

**Bootstrap이란?** CSS **프론트엔드 프레임워크(툴킷)**.

- 모바일, 태블릿, 데스크탑 등 **다양한 기기 환경**에서 웹 페이지가 적절히 표시되도록 **반응형 웹 디자인을 지원**하는 도구.
- **트위터(Twitter) 팀**에서 만들었다.

## 2. CDN (Content Delivery Network)

**콘텐츠를 더 빠르게, 사용자와 가깝게** 전달하기 위한 기술.

### 문제 상황

미국에 있는 서버의 데이터를 한국 사용자가 받으려면, **물리적 거리로 인해 지연(latency)**이 발생한다.

### 해결 방식

**서비스 센터(서버)를 전 세계 여러 곳에 대여**해서 물리적 거리의 한계를 극복한다.

| 용어 | 역할 |
|------|------|
| **오리진 서버 (Origin Server)** | 원본이 저장된 **메인 서버** |
| **엣지 서버 (Edge Server)** | 주요 거점에 **분산 배치**된 서버 |

- 사용자와 **가장 가까운 엣지 서버**가 요청을 감지하고, **복사본을 즉시 전송**한다.
- **효과:** 속도 향상, **서버 부하 분산**, 안정성 확보.

## 3. Bootstrap 파일 구조

### `bootstrap.min.css`

- Bootstrap의 **통합본(모든 스타일이 합쳐진 파일)**이다.
- **모두 클래스 선택자**로 구성되어 있다.

### 왜 "minified(축소됨)"인가?

**공백 자체도 데이터**이기 때문에, 레이턴시를 **마이크로초 단위라도 줄이기 위해 minify(압축)** 작업을 한다. (줄바꿈, 들여쓰기, 불필요한 공백을 모두 제거해 파일 크기를 최소화)

### `bootstrap.min.js`

- 이 JS는 **디자인 요소에 움직임(상호작용)이 있는 경우**, 그 움직임을 담당한다. (모달, 캐러셀, 드롭다운 등의 동작)
- 지금은 이 정도만 이해하고 넘어간다.

## 4. Bootstrap 기본 사용법

**클래스 이름으로 스타일 및 레이아웃이 미리 작성되어 있다.** 이름에는 **규칙성**이 있다.

```html
<div class="mt-5">...</div>   <!-- margin-top -->
```

### 이름 규칙 해독하기

| 코드 | 의미 |
|------|------|
| `m` | margin |
| `p` | padding |
| `t` | top |
| `b` | bottom |
| `s` | start (좌측, `left`의 논리적 표현) |
| `e` | end (우측, `right`의 논리적 표현) |
| `x` | 좌우(左右, left+right) |
| `y` | 위아래(上下, top+bottom) |

### 사이즈(숫자) 값

Bootstrap은 숫자로 크기 단계를 정의한다.

| 숫자 | 값 |
|:----:|-----|
| `0` | `0` |
| `1` | `0.25rem` |
| `2` | `0.5rem` |
| `3` | `1rem` |
| `4` | `1.5rem` |
| `5` | `3rem` |
| `auto` | `auto` |

```html
<div class="mt-5"></div>   <!-- margin-top: 3rem; -->
<div class="px-3"></div>   <!-- padding-left: 1rem; padding-right: 1rem; -->
<div class="mb-auto"></div> <!-- margin-bottom: auto; -->
```

### Bootstrap은 왜 `!important`를 쓸까?

**Bootstrap이 다른 CSS(개발자가 작성한 스타일)에 먹히면 안 되기 때문**이다. 프레임워크가 제공하는 유틸리티 클래스는 어떤 상황에서도 의도대로 적용되어야 하므로, 명시도 경쟁에서 지지 않도록 `!important`를 사용한다.

> 관련 내용은 **공식 문서에 준비되어 있다.**

## 5. 리셋 CSS (Reset CSS)

**모든 HTML 요소의 스타일을 일관된 기준으로 재설정**하는 간결하고 압축된 규칙 시트.

- `<h1>`, `<table>`, `<li>` 등 다양한 HTML 요소들에 **일관성 있게 스타일을 적용시키는 기본 단계**.

### 문제 상황 — 브라우저마다 기본 스타일이 다르다

모든 브라우저는 **유저 에이전트 스타일 시트(User Agent Stylesheet)**라는 **내장 스타일 시트**를 갖고 있다.

- **문제는 이 기본 설정이 브라우저마다 상이하다는 것.** (같은 `<h1>`이라도 브라우저마다 기본 여백·크기가 다를 수 있음)
- 그래서 "**모든 브라우저에서 똑같이 보이게 하자**"는 목적으로 리셋 CSS가 등장했다.

### Bootstrap의 해결책 — Reboot

- Bootstrap에는 **Reboot**이라는 CSS가 있고, **풀 패키지(`bootstrap.min.css`)에 포함**되어 있다.
- **초기화(리셋)만 필요하다면 Reboot만 따로 사용**할 수도 있다.

### Normalize.css

- **IE(Internet Explorer)와 Edge**가 문제였다 — 이들은 **웹 표준을 지원하지 않는 부분**이 있었다.
- 이 경우, **IE와 Edge의 스타일을 나머지(표준을 잘 지키는) 브라우저에 맞춰 적용**시키는 방식으로 통일한다.
- **Bootstrap의 Reboot도 이 방법(Normalize.css의 접근 방식)을 기반**으로 한다.

## 6. Bootstrap 활용 — 스타일 도구들

### 타이포그래피 (Typography)

**Display 헤딩** — 일반 헤딩(`<h1>`~`<h6>`)보다 **더 눈에 띄는 제목**이 필요할 경우 사용.

```html
<h1 class="display-6">더 크고 눈에 띄는 제목</h1>
```

### 컬러 시스템 (Color System)

**의미론적 관점**의 색상을 적용할 수 있게 해준다. (색상 자체의 이름이 아니라, **역할**에 따라 이름 붙여짐)

```
primary, secondary, success, danger, warning, info, light, dark
```

### 보더(Border) 등 기타 유틸리티

Bootstrap에는 이 외에도 다양한 유틸리티 클래스(그림자, 정렬, 표시/숨김 등)가 있다.

> **학습 태도:** 이런 세부 유틸리티까지 전부 외워서 정리해둘 필요는 없다. 실무에서는 **필요할 때 공식 문서를 찾아 쓰면 되므로**, "이런 게 있다"는 정도만 인지하고 넘어가는 게 효율적이다.

## 7. 컴포넌트 (Component)

**"레고 블록"** — 재사용 가능한 독립적인 부품으로, 더 크고 복잡한 시스템을 구축하기 위해 사용되는 소프트웨어의 단위.

### 대표 컴포넌트

- **Alert** (알림 메시지)
- **Card** (카드)
- **Navbar** (내비게이션 바)
- **Carousel** (캐러셀, 슬라이드)

### ⚠️ 상호작용하는 컴포넌트 사용 시 주의사항

컴포넌트를 사용하면 코드에 **`data-bs-target`**이 많이 보이는데, **클릭했을 때 상호작용하는 컴포넌트(캐러셀, 모달 등)는 이 부분을 특히 주의해야 한다.**

#### 캐러셀(Carousel)

캐러셀의 **`id`**와, 버튼(이전/다음, 인디케이터)의 **`data-bs-target`**이 **서로 정확히 일치하는지 확인**해야 한다. 하나라도 어긋나면 버튼이 캐러셀을 제어하지 못한다.

#### 모달(Modal)

클릭하면 팝업이 뜨고 뒤 배경이 어두워지는 그 UI.

- 모달도 마찬가지로 **`data-bs-target`**을 주의해야 한다.
- **모달의 본체는 평소에는 화면에 보이지 않는다.** (숨겨져 있다가 트리거되면 나타남)

**모달 코드의 위치 관례:**

- 모달 코드는 보통 길기 때문에, 이걸 버튼 바로 옆(중간)에 두면 코드 전체를 읽을 때 불편하다.
- **모달은 반드시 버튼 코드와 함께 붙어 있을 필요가 없다.**
- 오히려 모달 코드가 **다른 요소(특히 `overflow: hidden`이나 `position` 관련 스타일을 가진 요소)에 중첩**되면, 모달이 **검은 배경(오버레이) 뒤로 가려지거나 제대로 안 뜨는 문제**가 생길 수 있다.
- 그래서 모달은 **다른 요소에 중첩되지 않는 위치**에 두는 것이 안전하며, 관례적으로 **`</body>` 태그가 닫히는 곳 바로 위에 모아두는 것이 일반적**이다.

### 컴포넌트의 특징 및 장점

| 특징 | 설명 |
|------|------|
| **사용성** | 한 번 잘 만들어둔 코드는 **여러 페이지에서 반복해서 사용** 가능 |
| **독립성** | 다른 코드와 얽히지 않고 독립적으로 동작 |
| **유지보수 용이성** | 컴포넌트 하나만 고치면 그걸 쓰는 모든 곳에 반영됨 |

## 8. HTML 시맨틱 엘리먼트 (Semantic Elements)

### 시맨틱 웹(Semantic Web)이란?

**웹 데이터를 의미론적으로 구조화된 형태로 표현하는 방식.**

### 시맨틱 엘리먼트 예시

```
<header>, <nav>, <main>, <footer>, <article>, <section> ...
```

- 이 태그들은 **기능적으로는 `<div>`와 같다.** (레이아웃 상 특별한 동작 차이는 없음)
- 하지만 **시맨틱 엘리먼트를 쓰면 SEO(검색 엔진 최적화)에 유리**하다.
- **검색 봇(크롤러)이 문서 구조를 파악하기 더 편하다.** (`<div id="header">`보다 `<header>`가 "이건 헤더 영역이다"라는 의미를 명확히 전달)

## 9. CSS 방법론 (CSS Methodology)

**"클래스 이름을 어떻게 지을 것인가?"**에 대한 체계적인 접근 방식.

### OOCSS (Object-Oriented CSS)

**객체지향적 접근법을 적용하여 CSS를 구성하는 방법론.**

핵심 원칙: **구조(Structure)와 스킨(Skin)을 분리**한다. (예: 컨테이너와 콘텐츠를 분리)

#### 예시 1 — 왜 구조와 스킨을 분리해야 하는가

**Bad (나쁜 예):**

```css
/* bad */
.blue-button {
  border: none;
  font-size: 1em;
  padding: 10px 20px;
  background-color: blue;
  color: white;
}

.red-button {
  border: none;
  font-size: 1em;
  padding: 10px 20px;
  background-color: red;
  color: white;
}
```

- 하나의 선택자(`.blue-button`, `.red-button`)에 **구조**(`border`, `font-size`, `padding`)와 **색상**(`background-color`, `color`)에 대한 선언이 **혼재**되어 있다.
- **다른 색의 버튼을 추가할 때마다 구조 코드가 계속 반복**된다. (`border: none; font-size: 1em; padding: 10px 20px;`가 매번 중복)

**Good (좋은 예):**

```css
/* good */
.button {
  border: none;
  font-size: 1em;
  padding: 10px 20px;
}

.button-blue {
  background-color: blue;
  color: white;
}

.button-red {
  background-color: red;
  color: white;
}
```

- **구조(`.button`)**와 **색상(`.button-blue`, `.button-red`)을 나타내는 선택자를 분리**했다.
- 이제 **다른 색의 버튼을 추가할 때는 색상에 대한 선언만 새로 작성**하면 된다. (구조 코드 반복 없음)

```html
<button class="button button-blue">파란 버튼</button>
<button class="button button-red">빨간 버튼</button>
```

#### 예시 2 — 컨테이너와 콘텐츠 분리

**Bad (나쁜 예):**

```css
/* bad */
.header h2 {
  font-size: 24px;
  color: white;
}

.footer h2 {
  font-size: 24px;
  color: black;
}
```

`.header`와 `.footer` 클래스가 **폰트 크기와 색, 둘 다에 영향을 주고 있다.** (컨테이너 선택자 안에 콘텐츠 스타일까지 뒤섞여 있음)

**Good (좋은 예) — 역할 분리:**

```css
/* good */
.container .title {
  font-size: 24px;   /* 콘텐츠 스타일: 폰트 크기 담당 */
}

.header {
  color: white;        /* 컨테이너 스타일: 폰트 색 담당 */
}

.footer {
  color: black;        /* 컨테이너 스타일: 폰트 색 담당 */
}
```

- **`.container .title`**은 **폰트 크기**를 담당한다. (콘텐츠 스타일)
- **`.header`와 `.footer`**는 **폰트 색**을 담당한다. (컨테이너 스타일)

> **핵심 정리:** OOCSS는 "이 스타일이 **어떤 모양(구조)**을 결정하는가"와 "이 스타일이 **어떤 겉모습(스킨/색상)**을 결정하는가"를 **서로 다른 클래스로 분리**해서, **재사용성을 높이고 중복을 줄이는** 것이 핵심이다.
