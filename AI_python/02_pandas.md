# 데이터 다루기 — Pandas

## 1. 왜 Pandas인가? — NumPy의 문제점

NumPy만으로 데이터를 다루려고 하면 다음과 같은 한계가 있다.

- **여러 타입이 섞여있을 경우**, NumPy 배열은 같은 자료형만 담을 수 있어서 **전부 문자열로 처리**되어 버린다. (숫자와 문자가 섞인 데이터를 담으면 숫자도 문자열이 되어버려, "나이의 평균 같은 걸 구하기 힘들다.")
- **열 이름이 없다.** (몇 번째 열이 "나이"인지 기억해서 인덱스로 접근해야 함)
- **결측치(비어있는 데이터)를 처리할 방법이 없다.** 데이터가 비어있는 경우는 어떻게 하나?

> 이런 문제들을 해결하기 위해 **Pandas**가 등장한다.

---

## 2. Pandas 맛보기

```python
import pandas as pd

df = pd.read_csv("titanic.csv")   # csv 파일을 한 줄로 로딩

print("나이 평균: ", df["age"].mean())   # 나이 평균: 29.69911764705882  ::> 결측치는 알아서 제외
print("최고 요금: ", df["fare"].max())   # 최고 요금: 512.3292
print("여성의 생존률: ", df[df["sex"] == "female"]["survived"].mean())  # 0.742...
print("남성의 생존률: ", df[df["sex"] == "male"]["survived"].mean())    # 0.188...

# 아래의 한 줄로 "여성 생존률: 74.2%, 남성 생존률: 18.9%"를 알 수 있음
print("성별 생존률\n", df.groupby("sex")["survived"].mean())
# sex
# female    0.742038
# male      0.188908
# Name: survived, dtype: float64

print(df.index)
print(df.columns)
print(type(df["age"]))          # <class 'pandas.core.series.Series'>
print(type(df["age"].values))   # <class 'numpy.ndarray'>
```

> **눈여겨볼 점:** `df["age"].mean()`은 **결측치를 알아서 제외하고 계산**해준다. 앞서 NumPy의 한계로 지적했던 "결측치 처리"가 Pandas에서는 기본으로 처리된다는 걸 확인할 수 있다.
> 또한 `df["age"]`의 타입은 `pandas.Series`지만, `.values`로 꺼내면 그 안의 실제 데이터는 `numpy.ndarray`다. **Pandas는 내부적으로 NumPy 배열을 사용**한다는 것이 코드로도 드러난다.

## 3. DataFrame과 Series

| 개념 | 정의 |
|------|------|
| **DataFrame** | **행과 열로 구성된 2차원 표** |
| **Series** | **DataFrame의 한 열을 구성하는 1차원 자료구조** |

> `merge`: 두 표를 공통된 열/인덱스를 기준으로 결합하는 기능 (뒤에서 다룰 예정)

- **DataFrame은 열마다 다른 자료형을 사용할 수 있다.** (예: `지역` 열은 문자열, `단가` 열은 정수로 구성 가능)
- 반면 **NumPy 배열은 하나의 배열에 같은 자료형만 사용**할 수 있다. — 이게 바로 앞서 말한 NumPy의 첫 번째 문제점이 Pandas에서 해결되는 지점이다.

### 시리즈(Series)와 데이터프레임(DataFrame)의 관계

**시리즈는 열(column) 하나.** 그 **시리즈(열)가 여러 개 모이면 DataFrame**이 된다.

## 4. 언제 NumPy를, 언제 Pandas를 쓰나?

| 단계 | 도구 |
|------|------|
| 데이터를 **읽고, 정리하고, 탐색**하는 단계 | **Pandas** |
| 정리가 끝난 **순수 숫자 행렬을 계산**하는 단계 | **NumPy** |

> 비유하자면, **Pandas는 "이름표 달린 NumPy + 엑셀"**이다. Pandas가 데이터를 다듬어 순수한 숫자 배열로 만들어주면, 그 뒤의 빠른 수치 연산은 NumPy(Pandas 내부에서도 이미 NumPy를 쓰고 있음)가 담당하는 흐름이라고 이해하면 된다.

---

## 5. Pandas vs 엑셀 비교하기

Pandas의 많은 개념은 엑셀의 개념과 1:1로 대응된다.

| 엑셀 | Pandas |
|------|--------|
| 엑셀 시트 | **DataFrame** |
| 엑셀의 행/열 | **DataFrame의 행/열** |
| 엑셀 VLOOKUP | **merge** |
| 엑셀 피벗 테이블 | **groupby** |

> **행렬 == 행렬.** 결국 엑셀 시트에서 하던 작업(찾아보기, 합치기, 요약하기)을 코드로, 더 빠르고 재사용 가능하게 하는 것이 Pandas라고 생각하면 이해가 쉽다.

## 6. DataFrame이 하는 일 — 분석 과정의 흐름

| 단계 | 무엇을 하나 |
|------|-------------|
| **조회** | `df`, `.head()`, `.info()` — 일부 데이터와 자료형을 확인 |
| **필터** | `df[조건]` — 조건을 만족하는 행을 선택 |
| **집계** | `.groupby()` — 데이터를 그룹별로 묶어 요약 |

### 일반적인 데이터 분석 과정

> **파일 불러오기 → 조회 → 필터 → 집계 → 시각화** 순서로 진행한다.

## 7. 조회 메서드

> - **결측값(Missing Value)**: 값이 비어 있거나 누락된 데이터.
> - **요약 통계(Summary Statistics)**: 데이터의 개수, 평균, 표준편차, 최솟값, 최댓값 등 분포를 요약한 통계값.

| 메서드, 속성 | 반환값 | 용도 | 예시 |
|--------------|--------|------|------|
| `head(n)` | DataFrame | **위에서 n개** 행을 확인 | `df.head(10)` |
| `tail(n)` | DataFrame | **아래에서 n개** 행을 확인 | `df.tail(5)` |
| `info()` | 콘솔 출력 | **컬럼, 자료형, 결측값**을 확인 | `df.info()` |
| `describe()` | DataFrame | **수치형 데이터의 요약 통계**를 확인 | `df.describe()` |
| `shape` | 튜플 | **행과 열의 수**를 확인 | `df.shape` |
| `dtypes` | Series | **각 컬럼의 자료형**을 확인 | `df.dtypes` |
| `columns` | Index | **컬럼 이름**을 확인 | `df.columns` |

> **처음 데이터를 받으면 가장 먼저 해야 할 일:** `df.head()`로 생김새를 보고, `df.info()`로 결측치와 자료형을 확인하고, `df.describe()`로 수치형 데이터의 분포 감을 잡는 것 — 이 세 가지가 탐색의 출발점이다.

## 8. 조건 필터링 시 자주 하는 실수

> **연산자 우선순위(Operator Precedence)**: 여러 연산자를 함께 사용했을 때 **어떤 연산을 먼저 수행할지 정한 규칙.**

### 핵심 규칙

- **`and`, `or` 대신 `&`, `|`를 사용**해야 한다. (Pandas의 조건 필터는 파이썬 내장 논리 연산자를 지원하지 않음)
- **각 조건은 괄호로 감싸서 구분**해야 한다: `(df["매출"] >= 10000)`
- `==`는 **두 값이 같은지 비교**하는 것이고, `=`는 **변수에 값을 대입**하는 것이다. **조건 필터에서는 비교 연산자인 `==`를 사용**해야 한다.
- **한글 컬럼도** `df["지역"]` 형식으로 문제없이 접근 가능하다.
- **괄호를 생략하면 연산자 우선순위로 인해 오류가 발생하거나, 의도와 다른 결과가 나올 수 있다.**

### 실수 예시 1 — 괄호 누락으로 인한 TypeError

```python
# 괄호 누락 (에러)
df[df['매출'] >= 10000 & df['메뉴'] == '아메리카노']   # TypeError

# 올바른 작성
df[(df['매출'] >= 10000) & (df['메뉴'] == '아메리카노')]
```

> **왜 에러가 날까?** `&` 연산자가 `>=`, `==`보다 **연산자 우선순위가 더 높기** 때문에, 괄호 없이 쓰면 파이썬이 `10000 & df['메뉴']`를 먼저 계산하려고 시도하면서 타입이 맞지 않아 에러가 난다. 괄호로 각 조건을 명확히 묶어야 의도한 순서대로 계산된다.

### 실수 예시 2 — `and`를 쓰면 ValueError

```python
df[(df.수량 > 1) and (df.매출 > 9000)]
# ❌ ValueError: ambiguous  (Series의 진리값이 모호함)

df[(df.수량 > 1) & (df.매출 > 9000)]
# ✅ 정상 결과
```

> **왜 `and`는 안 될까?** 파이썬의 `and`/`or`는 **값 하나(스칼라)에 대한 참/거짓**을 판단하도록 설계되어 있다. 하지만 `(df.수량 > 1)`은 하나의 값이 아니라 **여러 개의 True/False로 이루어진 Series 전체**다. "이 Series가 전체적으로 참이냐 거짓이냐"는 파이썬 입장에서 **모호(ambiguous)**하기 때문에 에러가 난다. `&`, `|`는 **Series의 각 원소끼리 비트 단위로 비교**하도록 설계되어 있어서, 이런 "여러 개의 참/거짓 값 묶음"을 다루기에 적합하다.

## 9. 다중 값 필터와 문자열 검색

| 메서드 | 설명 |
|--------|------|
| `.isin([값1, 값2])` | **목록에 포함된 값**을 가진 행을 선택 |
| `.str.contains("문자")` | 컬럼 값에 **특정 문자가 포함되어 있는지** 확인 |
| `.str.startswith("문자")` | 컬럼 값이 **특정 문자로 시작하는지** 확인 |

```python
# 아메리카노 또는 카페라떼만
df[df['메뉴'].isin(['아메리카노', '카페라떼'])]
# → 2개 메뉴에 해당하는 행

# 메뉴명에 '라떼' 포함
df[df['메뉴'].str.contains('라떼')]
# → '라떼'가 들어간 모든 행 (카페라떼, 바닐라라떼 등)

# 서울이면서 매출 1만원 이상
df[(df['지역'] == '서울') & (df['매출'] >= 10000)]
# → 서울 지역의 고매출 행
```

> `.isin()`은 **"OR 조건을 나열해서 쓰는 것"의 축약형**이라고 이해하면 편하다. (`df['메뉴'] == '아메리카노' | df['메뉴'] == '카페라떼'`를 훨씬 간결하게 쓴 것) `.str.contains()`, `.str.startswith()`는 문자열 컬럼에서 **부분 문자열 검색**을 할 때 쓴다.

## 10. `loc` vs `iloc`

> **라벨(Label)**: 인덱스나 컬럼 이름처럼, **행과 열을 구분하는 이름.**

**`loc`은 이름표(Label) 기반**, **`iloc`은 순서(위치, integer position) 기반**이다.

| 구분 | `df.loc` | `df.iloc` |
|------|----------|-----------|
| **기준** | **라벨(label) 기반** | **위치(Position) 기반** |
| **행 인덱스** | 행 라벨(label) 사용 (`0`, `'a'`, 날짜 등) | 행의 **숫자 위치**(index) 기준 (0번째, 1번째...) |
| **열 인덱스** | 열 이름(label) 사용 (`'name'`, `'age'` 등) | 열의 **숫자 위치** (0, 1, 2...) |
| **끝 값 포함 여부** | 슬라이싱 시 **끝 값 포함** | 슬라이싱 시 **끝 값 미포함** (Python의 List와 같은 슬라이싱 규칙) |
| **비유** | **301호 우편함** (301호라는 **이름**으로 찾음) | **왼쪽에서 3번째 우편함** (자리, **순서**로 찾음) |

### `loc` 라벨 인덱싱

**`.loc[행 조건, 열 이름]`**: 행의 조건과 열 이름으로 데이터를 선택한다.

| 방식 | 설명 |
|------|------|
| `df[조건]` | 조건에 맞는 **행**을 선택 |
| `.loc` | **행과 열을 함께 선택**하거나, **값을 변경**할 때 사용 |
| `.iloc[행 위치, 열 위치]` | **정수 위치**로 행과 열을 선택 |

```python
# 서울 지역의 매출만 조회
df.loc[df['지역'] == '서울', '매출']

# 조건에 맞는 값 대입 (조건부 대입)
df.loc[df['단가'] < 4000, '단가'] = 4000

df.iloc[0, 1]   # 0행 1열 (위치 기반)
```

> **`loc`이 특히 헷갈리는 이유:** `df[조건]`은 "행만" 고를 수 있지만, `.loc[조건, 열이름]`은 **"행 조건 + 열 선택"을 한 번에** 할 수 있고, **더 나아가 조건에 맞는 자리에 값을 새로 대입(수정)까지 할 수 있다.** 즉 `.loc`는 단순 조회를 넘어 **"조건에 맞는 곳만 골라서 값을 바꾸는" 조건부 대입**에도 쓰인다는 점이 핵심이다. (`df.loc[df['단가'] < 4000, '단가'] = 4000`처럼 — 단가가 4000 미만인 행만 골라서 그 단가 값을 4000으로 일괄 수정)

**행 이름표(index) 예시:** `a, b, c, d, e, f, g`처럼 숫자가 아닌 라벨을 인덱스로 쓸 수도 있다. 이 경우 `df.loc['c']`는 **인덱스 이름이 `'c'`인 행**을 찾지만, `df.iloc[2]`는 **위치상 3번째(0부터 세어 인덱스 2번)인 행**을 찾는다 — 인덱스 이름이 `'c'`인 행과 위치상 3번째 행이 항상 같은 행이라는 보장은 없다는 점에서 둘의 차이가 분명해진다.

## 11. GroupBy 집계

**`groupby("컬럼")`**: **같은 값을 가진 행을 그룹으로 묶는다.**

- 그룹별로 `sum`, `mean`, `count`, `max` 등의 **집계 함수를 적용**한다.
- **엑셀의 피벗 테이블과 비슷한 방식**으로 데이터를 요약한다.

```python
# 지역별 합계 매출
df.groupby('지역')['매출'].sum()

# 메뉴별 평균 단가
df.groupby('메뉴')['단가'].mean()

# 지역별 주문 건수
df.groupby('지역')['메뉴'].count()
```

## 12. GroupBy 주의사항

> **NaN(Not a Number)**: 판다스에서 **수치형 데이터의 결측값**을 나타낼 때 주로 사용하는 특수한 값.

| 표현 | 설명 |
|------|------|
| `["매출"]` | **하나의 집계 컬럼**을 선택해 **Series로 반환** |
| `[["매출", "수량"]]` | **여러 집계 컬럼**을 선택해 **DataFrame으로 반환** |
| `.count()` | **NaN을 제외한 값의 개수**를 계산 |
| `.size()` | **NaN을 포함한 전체 행 수**를 계산 |
| `.mean()` | **NaN을 제외하고 평균**을 계산 |
| `inplace=True` | **원본을 변경**하므로, 필요한 경우 결과를 새로운 변수에 저장해야 함 |

```python
df.groupby('지역')['매출'].sum()           # Series 반환
df.groupby('지역')[['매출', '수량']].sum()  # DataFrame 반환

df.groupby('지역')['메뉴'].count()   # NaN 제외한 개수
df.groupby('지역').size()             # NaN 포함한 전체 행 수
```

> **`count()`와 `size()`의 차이가 핵심 포인트다.** 데이터에 결측치(NaN)가 섞여 있는 컬럼을 기준으로 `count()`를 쓰면 **NaN인 행은 세지 않지만**, `size()`는 **NaN 여부와 상관없이 그 그룹에 속한 행 전체를 센다.** 두 값이 다르게 나온다면, 그 차이만큼 결측치가 있다는 뜻이므로 데이터 품질을 점검하는 신호로도 활용할 수 있다.

> **`inplace=True` 사용 시 주의:** 이 옵션을 쓰면 **원본 DataFrame 자체가 바뀌어버린다.** 원본을 보존하고 싶다면 `inplace=True`를 쓰지 않고, **결과를 새로운 변수에 저장**하는 방식(`df2 = df.groupby(...)`)을 쓰는 게 안전하다.

## 13. 다중 GroupBy — 여러 컬럼 기준으로 묶기

`groupby()`에 **리스트로 여러 컬럼**을 넘기면, **그 컬럼들의 조합마다** 그룹이 나뉜다.

```python
# 지역별 + 메뉴별 매출 합계
df.groupby(['지역', '메뉴'])['매출'].sum()
```

```
지역   메뉴
서울   아메리카노    45000
       카페라떼      32000
부산   아메리카노    28000
       카페라떼      19000
Name: 매출, dtype: int64
```

> **읽는 법:** 첫 번째로 넘긴 컬럼(`지역`)이 **바깥쪽 그룹**, 두 번째로 넘긴 컬럼(`메뉴`)이 **안쪽 그룹**이 된다. 즉 "지역별로 크게 나눈 다음, 그 안에서 다시 메뉴별로 나눈다"는 뜻이다. 리스트 순서를 바꾸면 그룹의 바깥/안쪽 관계도 뒤바뀐다.

### 여러 컬럼으로 묶은 결과를 다시 표로 펼치기 — `reset_index()`

```python
result = df.groupby(['지역', '메뉴'])['매출'].sum().reset_index()
```

```
   지역     메뉴       매출
0  서울   아메리카노   45000
1  서울   카페라떼     32000
2  부산   아메리카노   28000
3  부산   카페라떼     19000
```

> `groupby()`만 쓰면 결과가 `지역`, `메뉴`가 **인덱스**로 들어간 형태가 되는데, 이러면 나중에 다시 일반 컬럼으로 다루기 불편할 때가 많다. `.reset_index()`를 붙이면 인덱스로 들어간 `지역`, `메뉴`를 **다시 평범한 컬럼**으로 꺼내준다. groupby 결과를 다른 DataFrame과 합치거나(`merge`), CSV로 저장할 때 특히 자주 쓰는 패턴이다.

## 14. `.agg()` — 여러 집계 함수를 한 번에 적용하기

`.sum()`, `.mean()`처럼 **집계 함수 하나만 쓰는 대신**, `.agg()`를 쓰면 **여러 집계를 동시에** 계산할 수 있다.

### 하나의 컬럼에 여러 함수 적용

```python
df.groupby('지역')['매출'].agg(['sum', 'mean', 'count'])
```

```
      sum      mean      count
지역
서울   77000   38500.0    2
부산   47000   23500.0    2
```

### 컬럼마다 서로 다른 함수 적용 — 딕셔너리로 지정

```python
df.groupby('지역').agg({
    '매출': 'sum',      # 매출은 합계
    '수량': 'mean',      # 수량은 평균
    '메뉴': 'count'      # 메뉴는 개수(주문 건수)
})
```

```
      매출     수량    메뉴
지역
서울   77000   2.5     2
부산   47000   1.8     2
```

> **`.agg()`가 필요한 이유:** `.sum()`, `.mean()`을 각각 따로 호출하면 결과가 매번 별개의 Series로 나와서, 이후 이를 다시 하나로 합치는 번거로운 작업이 필요하다. `.agg()`는 **원하는 통계를 한 번의 호출로 모두 계산해 하나의 표로** 만들어준다는 점에서, 엑셀에서 피벗 테이블에 "값 필드"를 여러 개 넣는 것과 같은 효과를 낸다.

### 컬럼 이름까지 직접 지정하기 — Named Aggregation

```python
df.groupby('지역').agg(
    총매출=('매출', 'sum'),
    평균수량=('수량', 'mean'),
    주문건수=('메뉴', 'count')
)
```

```
      총매출    평균수량   주문건수
지역
서울   77000    2.5        2
부산   47000    1.8        2
```

> 이 방식을 쓰면 결과 컬럼 이름을 **원하는 대로 직접 지정**할 수 있어서, 앞서처럼 `sum`, `mean`이 그대로 컬럼명이 되는 것보다 **가독성이 훨씬 좋다.** 실무에서는 이 방식을 선호하는 경우가 많다.

## 15. `pivot_table` — 엑셀 피벗 테이블에 대응

`groupby`가 결과를 **위아래로 긴 표(long format)**로 만든다면, `pivot_table`은 결과를 **엑셀 피벗 테이블처럼 행×열의 넓은 표(wide format)**로 만들어준다.

```python
pd.pivot_table(
    df,
    values='매출',      # 집계할 값
    index='지역',        # 행으로 놓을 기준
    columns='메뉴',      # 열로 놓을 기준
    aggfunc='sum'        # 집계 함수
)
```

```
메뉴    아메리카노   카페라떼
지역
서울    45000       32000
부산    28000       19000
```

### `groupby` + `unstack()`으로도 같은 결과를 만들 수 있다

```python
df.groupby(['지역', '메뉴'])['매출'].sum().unstack()
```

> 사실 `pivot_table`은 내부적으로 **`groupby` + `unstack()`(세로로 긴 결과를 가로로 펼치는 것)을 합쳐놓은 것**과 결과가 같다. 다만 `pivot_table`은 **"행 기준 / 열 기준 / 집계 값"을 한 번에 명시**할 수 있어서, 엑셀 피벗 테이블에 익숙한 사람에게는 더 직관적인 인터페이스다.

### 결측치를 기본값으로 채우기 — `fill_value`

```python
pd.pivot_table(
    df,
    values='매출',
    index='지역',
    columns='메뉴',
    aggfunc='sum',
    fill_value=0        # 데이터가 없는 조합은 0으로 채움
)
```

> 예를 들어 "부산 지역에는 카페라떼 주문이 아예 없었다"면, 그 칸은 기본적으로 **NaN**으로 비어있게 된다. `fill_value=0`을 주면 이런 빈 칸을 **0으로 채워서**, 표를 볼 때 "주문이 없어서 0인지" "데이터를 못 읽어서 비었는지" 헷갈리지 않게 만들 수 있다.

### 여러 집계 함수를 동시에 — `aggfunc`에 리스트 전달

```python
pd.pivot_table(
    df,
    values='매출',
    index='지역',
    columns='메뉴',
    aggfunc=['sum', 'mean']
)
```

> `aggfunc`에 리스트를 넘기면, **각 집계 함수별로 결과가 나란히** 표시된다. `.agg()`와 마찬가지로 여러 통계를 한 번에 뽑아낼 수 있는 것이다.

## 16. 세 방식 비교 정리

| | `groupby()` 단독 | `groupby().agg()` | `pivot_table()` |
|---|---|---|---|
| 결과 모양 | 세로로 긴 표 (long format) | 세로로 긴 표, 여러 통계량 포함 | **가로×세로 넓은 표** (wide format) |
| 강점 | 가장 기본적, 단순 집계에 빠름 | 여러 통계를 한 번에 계산 | 엑셀 피벗 테이블처럼 **한눈에 비교**하기 좋음 |
| 언제 쓰나 | 하나의 통계값만 빠르게 확인할 때 | 그룹별로 여러 지표(합계, 평균, 개수 등)를 동시에 보고 싶을 때 | 두 기준(행/열)으로 교차 비교하는 표가 필요할 때 |
