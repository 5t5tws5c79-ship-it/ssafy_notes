## 2. 오토그래드 (Autograd)

- 파이토치의 **핵심 기능**
- `loss.backward()` **단 한 줄**만 실행하면, 앞서 배운 복잡한 **역전파 과정을 모두 자동으로 계산**해주는 강력한 엔진

**동작 원리 (참고)**
- 텐서에 `requires_grad=True`를 주면, 그 텐서에 가해지는 모든 연산이 추적됨
- `.backward()`를 호출하는 순간, 지금까지 추적된 연산 그래프를 거꾸로 따라가며(=역전파) 모든 기울기를 한 번에 계산
- 계산된 기울기는 `텐서.grad`에 저장됨

```python
x = torch.tensor([2.0, 3.0], requires_grad=True)
y = x**2 + 3*x + 1
z = y.sum()
z.backward()
print(x.grad)  # tensor([7., 9.])  (dy/dx = 2x+3 이므로 x=2→7, x=3→9)
```

> ⚠️ 기울기는 덮어쓰이지 않고 **누적**된다 — 그래서 매 스텝마다 `optimizer.zero_grad()`로 초기화해줘야 함 (6장에서 다시 등장)

## 3. 모델 정의 및 데이터 준비

### 모델 정의

- `__init__`에서 모델에 필요한 **레고 블록들(레이어)**을 정의
- `forward`에서 그 블록들을 **어떤 순서로 조립할지(데이터가 어떤 순서로 통과할지)** 설계

**실습에서 만들 MLP (코드)**

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(...)  # 레고 블록 조립

    def forward(self, x):
        return self.net(x)   # 조립 순서대로 실행
```

### 데이터 준비

- **데이터셋(Dataset)**: 전체 데이터를 담고 있는 것
- **데이터로더(DataLoader)**: 모델에게 데이터를 **미니배치 단위로 효율적으로 공급**하는 역할

```python
train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)
```

## 4. 성능 향상 — 똑똑하게 학습시키기

### 과적합과 규제

- **과적합(Overfitting)**: 모델이 훈련 데이터만 너무 열심히 외워서, 처음 보는 테스트 데이터에 대한 응용력이 떨어지는 현상
- **규제(Regularization)**: 과적합을 막기 위해 모델에 **제약을 거는 기법**

### 드롭아웃 (Dropout)

- **훈련 시**: 은닉층의 뉴런을 **일정 확률로 랜덤하게 꺼버림(off)**
- **추론(평가) 시**: 뉴런을 **전부 켜둠(on)**

**효과**
- 특정 뉴런에 지나치게 의존하는 것을 방지
- 매번 다른(부분) 네트워크를 학습시키는 듯한 **'앙상블 효과'**를 냄

```python
nn.Dropout(p=dropout)  # 학습 중 p의 확률로 뉴런을 랜덤하게 꺼버림
```

> `model.train()` 일 때 Dropout ON, `model.eval()` 일 때 Dropout OFF — 평가할 때 `model.eval()`을 빠뜨리면, 뉴런이 랜덤하게 꺼진 채로 평가되어 "실행할 때마다 정확도가 달라지는" 문제가 생김

## 5. 훈련 종료 시점 정하기 — 얼리 스타핑

- 순전파 → 손실 계산 → 역전파 → 가중치 업데이트, 이 한 바퀴가 **1 에포크**
- 에포크를 많이 반복하는 것만이 훈련의 전부는 아님 — **언제 멈출지**도 중요

### 얼리 스타핑 (Early Stopping)

- 훈련에 사용되지 않은 **검증 데이터**로 주기적으로 "모의고사"를 침
- 검증 데이터에 대한 손실이 더 이상 줄어들지 않고, 오히려 **증가하기 시작**하면 → 과적합의 신호로 판단
- **가장 성능이 좋았던 시점**에서 학습을 자동으로 멈추는 기법
- 가장 널리 쓰이는 과적합 방지 기술 중 하나

> (강의 중 "참고"라고 표시된 슬라이드/구간은 통째로 시험 범위에서 제외된다고 언급됨)

## 6. 옵티마이저 (Optimizer)

- 머신러닝에서 **손실함수의 값이 최소가 되는 최적의 가중치**를 찾기 위한 알고리즘
- **경사하강법도 옵티마이저의 하나** (가장 기본적인 형태)

### 경사하강법의 치명적 단점

학습률에 따라 다양한 문제가 발생

| 상황 | 문제 |
|------|------|
| 학습률이 **너무 높은** 경우 | 손실 함수 값이 줄어들지 않고 오히려 커지는 **오버슈팅(Overshooting)** |
| 학습률이 **너무 낮은** 경우 | 학습이 너무 느리고, **지역 최저점(local minimum)**에 한 번 빠지면 빠져나오기 힘듦 |

> 그래서 등장한 것이 **Adam** — 현재 표준으로 널리 쓰이는 옵티마이저. 핵심은 **학습률을 적응적으로 조절**하는 것.

### Adam (Adaptive Moment Estimation)

**1. 관성(Momentum) 도입**
- 현재 위치의 기울기만 보고 움직이는 경사하강법과 다르게, **이전까지 이동해 온 '속도와 방향(관성)'을 기억**
- 양쪽 벽으로 요동치는 움직임을 상쇄하고, 관성을 이용해 부드럽게 내려가게 만듦
- 잠시 '지역 최저점'에 빠지더라도, 관성의 힘으로 지역 최저점을 빠져나올 수 있음

**2. 적응적 학습률(Adaptive Learning Rate) 도입**
- 가중치마다 "고유한 학습률"을 부여하여, 최적의 학습 속도를 유지하며 효율적으로 낮은 손실 지점에 도달
- **많이** 움직였던 가중치에 대해서는 학습률을 **작게** 만들어서, **적게** 움직이도록 함
- **적게** 움직였던 가중치에 대해서는 학습률을 **크게** 만들어서, **빠르게** 학습을 진행

> 아담(Adam)은 이전까지의 속도와 방향을 누적해서 기억하기 때문에, 잠시 지역 최저점에 빠져도 관성의 힘으로 빠져나올 수 있음

### 지금은 AdamW를 쓴다

- Adam에서 **가중치 감쇠(Weight Decay)**가 제대로 동작하지 않는 문제가 발견되어, 이를 분리해서 고친 것이 **AdamW**
- **AdamW가 현재 LLM/트랜스포머 학습의 표준** 옵티마이저

> `[개인 메모 · 시험범위 아님]` 질문: 웨이트 디케이??? L2 규제가 뭔지 설명해줘
>
> **답변**
>
> **① L2 규제(L2 Regularization)란?**
> 손실함수에 "가중치의 크기에 비례하는 벌점(penalty)"을 추가로 더해주는 방법이다.
> - 원래 손실 = 데이터를 얼마나 잘 맞췄는지만 반영 (예: MSE, 교차 엔트로피)
> - L2 규제를 더한 손실 = **원래 손실 + λ × Σ(가중치²)** (λ는 규제 강도를 조절하는 하이퍼파라미터, Σ(가중치²)는 모든 가중치를 제곱해서 더한 값)
> - 즉 "정답을 잘 맞추면서도, 가중치 값 자체는 너무 커지지 않게" 유도하는 것
>
> **왜 가중치가 커지면 안 좋은가?** 가중치가 매우 크면, 입력값의 아주 작은 변화에도 모델의 출력이 지나치게 민감하게 반응하게 된다. 이런 모델은 훈련 데이터의 미세한 노이즈까지 과하게 반영해버리는, 즉 **과적합**에 취약한 상태가 되기 쉽다. 반대로 가중치를 작게(0에 가깝게) 유지하도록 유도하면, 모델이 더 "부드럽고 단순한" 함수를 학습하게 되어 일반화 성능이 좋아지는 경향이 있다.
>
> **② Weight Decay와 L2 규제의 관계**
> 이론적으로 (Adam이 아닌 기본) 확률적 경사하강법(SGD)에서는, "L2 규제를 손실함수에 추가하는 것"과 "매 업데이트 스텝마다 가중치 값을 일정 비율로 살짝 줄여주는 것(weight decay)"이 수학적으로 **동일한 효과**를 낸다. 그래서 오랫동안 "weight decay = L2 규제"로 취급되어 왔고, 초기 Adam 옵티마이저도 weight decay를 "손실함수에 L2 페널티를 더하는 방식"으로 구현했다.
>
> **③ 그런데 Adam에서는 왜 문제가 생겼나?**
> Adam은 가중치마다 "적응적 학습률"을 따로 계산해서 사용한다. 그런데 L2 규제를 손실함수에 단순히 더해서 넣으면, 이 규제로 인한 벌점(패널티) 효과까지도 Adam의 "적응적 학습률 계산" 과정에 함께 휩쓸려 들어가 버린다. 그 결과, 원래 의도했던 "모든 가중치를 일정한 비율로 줄여주는" 깔끔한 효과가, 가중치마다 제각각으로 왜곡되어 버리는 문제가 발생한다 (L2 규제와 Adam의 적응적 학습률 메커니즘이 서로 간섭하는 것).
>
> **④ AdamW의 해결책**
> AdamW는 weight decay를 손실함수 안에 슬쩍 끼워 넣는 대신, **가중치를 업데이트하는 단계에서 별도로, 직접 적용**하도록 분리했다 (이를 "Decoupled Weight Decay"라고 부른다). 이렇게 분리하면 Adam의 적응적 학습률 계산과 weight decay가 서로 간섭하지 않고, 원래 의도한 대로 "모든 가중치를 일정 비율로 꾸준히 줄여주는" 규제 효과가 깨끗하게 작동한다. 그래서 AdamW가 현재 LLM·트랜스포머를 포함한 대부분의 최신 딥러닝 모델 학습의 표준 옵티마이저로 자리 잡았다.
