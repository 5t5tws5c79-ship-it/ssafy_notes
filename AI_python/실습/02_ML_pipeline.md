## 1. 데이터 EDA (탐색적 데이터 분석)

데이터를 본격적으로 분석하기 전에, 여러 각도에서 관찰하고 이해하는 과정.

**EDA가 하는 일**
1. 분석의 방향성 제시
2. 모델의 성능 향상
3. 새로운 인사이트 발견

**EDA의 하위 단계**: 확인 → 정제 → 개별 특징 분석 → 특징 간 관계 분석

> 이 단계들은 고정된 순서가 아니며, 반복적으로 왔다 갔다 하면서 분석함.

### 상관관계 (Correlation)

- **정의**: 두 변수가 함께 변화하는 관련성. 하나의 변수가 증가할 때 다른 변수가 일정한 관련성을 띄며 함께 변화하는지에 대한 지표
- 상관계수: 양의 상관관계 / 음의 상관관계
- **상관관계가 높다고 해서 인과관계를 의미하는 것은 아님** (뒤에서 더 자세히 다룸)

### 데이터 시각화 — Matplotlib과 Seaborn

- **Matplotlib**과 **Seaborn** 라이브러리 사용
- Seaborn은 Matplotlib을 더 예쁘고 통계적으로 의미 있는 그래프로 쉽게 만들어주는 라이브러리
- 진행 방식: Matplotlib으로 제목·축·라벨 등을 추가하고, Seaborn으로 데이터를 그래프로 그림

> `[개인 메모 · 시험범위 아님]` 질문: Matplotlib을 상속받아서 Seaborn을 구현했나? (다형성이 있는 건가?)
>
> **답변**: 정확히는 "상속(inheritance)"이 아니라 **"기반으로 만들어짐(구성/위임, composition)"**에 가깝다. Seaborn은 내부적으로 Matplotlib의 Figure/Axes 객체를 그대로 사용해서 그 위에 그림을 그리는 방식으로 동작하며, Seaborn 클래스가 Matplotlib 클래스를 직접 상속하는 구조는 아니다. 대신 Seaborn 함수들은 결과로 표준 Matplotlib의 Axes 객체를 반환하기 때문에, 이후 Matplotlib 함수(`plt.title()`, `ax.set_xlabel()` 등)로 자유롭게 꾸밀 수 있다. 즉 "상속"보다는 **"Matplotlib 위에 지어진 고수준 래퍼(wrapper) 라이브러리"**로 보는 게 더 정확하다. 다만 두 라이브러리의 객체가 서로 호환되어 매끄럽게 섞어 쓸 수 있다는 점에서, 인터페이스 차원의 유연함(다형성과 비슷한 효과)은 분명히 존재한다.

### 단변수 분석 (Univariate Analysis)

#### 히스토그램 (Histogram)

- 특정 수치형 변수 **하나**의 데이터 분포를 파악하기 위해 사용
- 단점: **구간(bin) 설정에 민감**함
- 봉우리가 2개 있다면? → 서로 다른 두 개의 하위 그룹 데이터가 섞여 있다는 의미. 각 그룹을 대표하는 봉우리가 생김

#### 박스플롯 (Box Plot)

- **이상치를 찾을 때 매우 유용**
- 단점: 데이터 개수를 파악하기 어렵고, 데이터의 구체적인 분포 형태를 알기는 어려움
- 구조: 상자 안에 전체 데이터의 절반이 들어 있고, **수염**이 정상 데이터의 끝, 나머지 점들이 이상치
- **무조건 이상치라고 지우면 안 됨** — 왜 이상치가 생겼는지를 반드시 생각해야 함

### 다변수 분석 (Multivariate Analysis)

#### 산점도 (Scatter Plot)

- 다변수 분석의 가장 기본. 점을 찍어 만드는 그래프
- 두 변수가 어떤 관계를 갖고 있는지 직관적으로 파악 가능, 패턴이나 이상치를 쉽게 발견
- 한계: 데이터가 너무 많으면 점들이 겹쳐서 분포 파악이 어려움. 차원이 높아지면 한계가 더 커짐

#### 히트맵 (Heatmap)

- 여러 숫자형 변수들 간의 크기(상관관계 등)를 색상으로 변환하여 보여줌
- 주로 상관관계 분석에 많이 사용, 직관적이고 다변량 관계 파악 가능
- 한계: 정확한 수치를 알기 어렵고, 변수가 너무 많아지면 히트맵이 지나치게 커지고 복잡해져 한눈에 파악하기 어려움

#### 페어 플롯 (Pair Plot)

- 대각선에는 각 성분의 **분포도**, 비대각선에는 두 성분 사이의 관계를 보여주는 **산점도**
- 한계: 변수가 너무 많아지면 계산이 오래 걸림 → 중요하다고 생각되는 몇 개의 변수만 골라서 그리는 것이 일반적

### 상관관계 ≠ 인과관계 — 유명한 예시

**상어 사고와 아이스크림 판매량**: 두 변수는 함께 움직이며 상관관계가 강함

- ❌ 잘못된 해석: "아이스크림을 많이 먹으면 상어에 물린다"
- ✅ 올바른 해석: **더운 날씨**라는 제3의 변수(잠재변수)가 두 현상 모두에 영향을 미침

> 상관관계가 강하게 보일 때는, 진짜 원인-결과 관계인지 우연인지, **숨은 제3의 변수 때문인지 반드시 의심할 것**

## 2. EDA 결과를 바탕으로 모델 학습 준비하기

모델에게 주어진 모든 데이터를 학습시킨다면, 새로운 데이터에서도 항상 좋은 결과를 낼까? → 아니다.

> `[개인 메모 · 시험범위 아님]` 데이터 전처리는 언제나 모델의 실제 사용 환경을 고려해야 한다. 음고(음악 높낮이) 예측 모델의 경우, 실제 사용 시의 에코(반향) 같은 변수에 영향을 받을 수도 있다.

### 과적합 vs 과소적합

- **과적합(Overfitting)**: 노이즈나 특이 패턴까지 학습해버려서 발생
- **과소적합(Underfitting)**: 모델이 너무 단순해서 훈련 데이터의 핵심 패턴조차 제대로 학습하지 못한 상태
- 과적합인지 과소적합인지 어떻게 알까? → 아래 데이터 분리를 통해 확인

### 훈련/테스트 데이터 분리

- 주어진 데이터를 **훈련 데이터**와 **테스트 데이터**로 분리
- 훈련 데이터: 모델을 학습시키는 용도. 현업에서는 보통 7:3, 8:2 정도의 비율로 분리
- 과적합 여부 확인: **테스트 로스가 다시 올라가기 시작하는 구간이 과적합 구간**

### 데이터 분리 코드

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y
)
```

| 요소 | 역할 |
|------|------|
| `train_test_split` | 주어진 데이터를 훈련/테스트 데이터로 분리하는 함수 |
| `test_size=0.3` | 전체 데이터 중 30%를 테스트용, 나머지 70%를 훈련용으로 분리 |
| `random_state` | 값을 고정해두면, 다시 섞어도 항상 동일한 분할 결과를 보장 |
| `stratify=y` | **매우 중요!** |

**stratify=y란?**

- 원본 데이터의 정답 비율을 분할된 데이터셋에도 **동일한 비율로** 나눠주는 옵션
- 훈련 데이터에는 정상 메일만 들어가고, 테스트 데이터에는 스팸이 쏠려버리는 현상을 방지
- **분류 문제에서는 필수**

> `[개인 메모 · 시험범위 아님]` 질문: 데이터가 충분히 크면 대충 나눠도 어차피 골고루 되지 않나? 어떤 클래스가 너무 작으면 쏠릴 수도 있겠네.
>
> **답변**: 직관이 정확하다. 데이터가 매우 크고 클래스 비율도 어느 정도 균형 잡혀 있다면, 무작위 분할만으로도 실제 비율과 비슷하게 나뉠 가능성이 높다(대수의 법칙). 하지만 문제는 ① 클래스 자체가 원래 불균형한 경우(예: 스팸 1%, 정상 99%)와 ② 데이터셋 크기가 커도 **소수 클래스의 절대 개수 자체가 적은 경우**다. 예를 들어 전체 100만 건 중 스팸이 500건뿐이라면, 무작위 분할 시 우연히 테스트셋에 스팸이 거의 안 들어가거나 지나치게 몰릴 가능성이 실제로 있다. `stratify=y`는 이런 위험을 원천 차단하면서도 계산 비용이 거의 들지 않기 때문에, 데이터가 크든 작든 **분류 문제에서는 그냥 항상 켜두는 것이 이득인 옵션**이라고 보면 된다.

### 스케일링 — 표준화 (다시 정리)

- 각 특성의 단위를 맞춰서 공평하게 만들어주는 과정 (개념은 이전에 다룬 표준화와 동일한 슬라이드)

**표준화 코드**

```python
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()

# fit: 훈련 데이터의 평균과 표준편차 계산
# transform: 데이터를 표준화
scaler.fit(X_train)
X_train_norm = scaler.transform(X_train)

# or
# fit_transform: fit과 transform을 한 번에 수행
X_train_norm = scaler.fit_transform(X_train)

# 테스트 데이터는 훈련 데이터의 통계량(평균, 표준편차)을 사용하여 변환
X_test_norm = scaler.transform(X_test)
```

> ⚠️ **주의 (이 규칙 자체는 시험범위)**: 테스트 데이터의 표준화는 반드시 **"훈련 데이터의 평균/표준편차"**를 활용해야 한다!!! (아래의 상세한 원리 설명만 시험범위가 아님)

- 테스트 데이터는 아직 학습하지 않은, **미래의 데이터**라는 가정
- 테스트 데이터의 평균/표준편차를 scaler에 반영한다면, **정답을 미리 훔쳐본 것**과 같아짐
- 이렇게 유출된 정보로 학습한 모델은 실제 현실에서 제대로 된 성능이 나오지 않음

> `[개인 메모 · 시험범위 아님]` 질문: 훈련 데이터의 평균/표준편차를 테스트 데이터의 표준화에 사용해야 하는 원리를 쉬운 말로 소상히 정리해줘, 잘 이해가 안 감.
>
> **답변 (쉬운 비유로)**: 시험을 본다고 생각해보자. "이번 시험 평균 점수가 70점이었다"는 건 시험이 다 끝나고 채점까지 마쳐야 알 수 있는 정보다. 그런데 시험을 보기 *전에* 미리 "이번 시험 평균이 70점일 거야"라는 정보를 알고 문제를 풀었다면? 그건 이미 답을 어느 정도 알고 시험에 들어간 것과 같아서, 그 점수는 진짜 실력을 정확히 보여주지 못한다.
>
> 표준화(scaling)도 마찬가지다. **"평균/표준편차"라는 값 자체가 이미 그 데이터셋에 대한 정보(통계적 요약)**다. 모델을 만들 때 우리는 "테스트 데이터 = 아직 세상에 나오지 않은, 미래에 만나게 될 새로운 데이터"라고 가정한다. 그런데 테스트 데이터의 평균/표준편차까지 계산해서 스케일링에 써버리면, 모델이 "미래 데이터가 대략 이런 분포를 가지고 있구나"라는 정보를 학습 단계에서 미리 알고 시작하는 셈이 된다. 이는 시험 문제를 풀기 전에 답의 힌트를 살짝 본 것과 같다 — 이런 상태를 **데이터 유출(data leakage)**이라고 부른다.
>
> 그래서 해결책은 간단하다: **평균/표준편차는 오직 훈련 데이터에서만 계산한다(`scaler.fit(X_train)`)**. 테스트 데이터를 변환할 때는, 훈련 데이터에서 이미 계산해 둔 평균/표준편차를 "그대로 가져다가" 적용만 한다(`scaler.transform(X_test)`). 이렇게 하면 테스트 데이터는 모델이 실전에서 처음 마주치는 완전히 새로운 데이터처럼 다뤄지게 되고, 그래야 테스트 성능이 "진짜 실력"을 정직하게 보여주게 된다.

### 성능평가 — 정확도의 한계 (예고편)

- **정확도(Accuracy)** = 맞은 개수 / 전체 개수
- 정확도가 아무리 높아도 안심할 수 없음 (자세한 내용은 다음 장에서)

### 회귀 vs 분류 (다시 정리)

- **회귀**는 숫자 맞추기, **분류**는 칸(범주) 맞추기
- 로지스틱 회귀의 원리: 직선으로 확률을 계산한 뒤, 0.5를 넘으면 1번 칸으로 분류
- **계산은 회귀, 결론은 분류** — 그래서 이름이 "로지스틱 **회귀**"

## 3. 모델의 성적표 확인하기 — 분류 모델 평가 지표

### 정확도만 믿으면 안 되는 이유

**암 진단 예시** — 이 경우엔 **False Negative(암을 놓치는 것)**가 위험한 상황

- 100명의 환자 중 1명만 암 환자일 때, 모델이 "모두 암이 아니다"라고 찍어도 정확도는 99%가 나옴
- 이런 경우 정확도는 모델의 성능을 심각하게 왜곡할 수 있음 → **어떤 실수를 했는지 들여다봐야 함**

**스팸 메일 예시** — 반대로 이 경우엔 **False Positive(정상 메일을 스팸으로 오분류)**가 더 위험한 상황
- 중요한 정상 메일이 스팸함으로 걸러지면 큰일 나는 상황이기 때문

### 혼동행렬 (Confusion Matrix) — 탐정 비유

**포지티브 = 우리가 찾는 것, 네거티브 = 우리가 안 찾는 것**

| 구분 | 탐정 비유 | 의미 |
|------|-----------|------|
| **TP** (True Positive) | 탐정이 진짜 범인을 범인이라고 예측 잘한 일 | 실제 양성 → 예측도 양성 |
| **TN** (True Negative) | 탐정이 무관한 시민을 시민이라고 예측 잘한 일 | 실제 음성 → 예측도 음성 |
| **FP** (False Positive) | 무고한 시민을 범인이라고 예측 (섣부른 판단, 억울한 사람 발생) | 실제 음성 → 양성으로 오판 |
| **FN** (False Negative) | 범인을 시민이라고 예측 (범인을 놓침) | 실제 양성 → 음성으로 오판 |

### 정밀도 (Precision)

- **모델의 예측을 얼마나 믿을 수 있는가** — "암이라고 한 사람 중 진짜 암인 사람"의 비율
- 모델의 예측이 얼마나 정교한지 나타냄. **진짜 믿을 수 있어야 할 때** 유용
- **FP를 낮추는 것이 중요** — 없는 걸 있다고 하면 큰일 나는 상황에서 유용 (스팸 메일 예시)

### 재현율 (Recall)

- **실제 양성인 대상 중에 얼마나 빠짐없이 찾아냈는지** — "실제 암 환자 중 얼마나 빠짐없이 찾아냈는지"
- **FN을 낮추는 것이 중요**
- **모델이 하나라도 놓치면 안 될 때** 유용 (산불 감지, 암 환자 진단 등)

> 정밀도와 재현율은 보통 **트레이드오프(trade-off)** 관계 — 하나를 높이면 다른 하나가 낮아지는 경향

### F1-score

- **정밀도와 재현율의 조화 평균**
- 두 지표를 모두 균형 있게 바라보는 **종합 성적표**
- 정확도보다 F1-score가 모델의 성능을 더 신뢰성 있게 나타내는 경우가 많음

### 내 문제엔 어떤 지표를 써야 할까?

**핵심 질문: "어느 실수가 더 아픈가?"**

| 상황 | 더 위험한 실수 | 중요 지표 |
|------|----------------|-----------|
| 중요 메일이 스팸함에 가면 큰일 | False Positive | **정밀도(Precision)** |
| 암 환자를 정상이라고 돌려보내면 큰일 | False Negative | **재현율(Recall)** |
| 둘 다 중요할 때 | FP, FN 모두 | **F1-score** |

## 4. 성능검증 (Validation)

평가한 점수가 정말 신뢰할 만할까?

### 파라미터 vs 하이퍼파라미터

| 구분 | 설명 |
|------|------|
| **파라미터** | 모델이 스스로 찾아내는 값 (예: w, b) |
| **하이퍼파라미터** | 사람이 미리 정해주는 값 (예: 학습률) |

- 어떤 방식(하이퍼파라미터 조합)이 좋은 성적을 받을 수 있는지 **미리 검증**해야 함
- 가장 높은 성적을 받는 방식을 채택해서 최종 성능 평가
- **검증을 테스트 데이터로 진행하면 데이터 유출이 발생함**

### 검증 데이터 (Validation Data)

- 비유: 수능을 보기 전에 여러 번의 모의고사를 풀어보며, 어떤 공부법이 나에게 잘 맞는지 찾는 과정
- 여러 학습 방법을 검증 데이터로 평가 → 최고의 학습 방법을 구분하기 위한 용도
- **검증 데이터는 학습 용도로 활용되지 않으며, 학습 데이터에서 따로 분리**
- 검증 데이터는 "최고의 학습 방법을 구분하기 위한 테스트 데이터"라고 볼 수 있음
- **테스트 데이터로 검증(모델 선택)을 하는 것은 데이터 유출!** 검증 데이터 없이 테스트 데이터로 계속 성능을 확인하면 데이터 유출이 발생함

> `[개인 메모 · 시험범위 아님]` 훈련/검증/테스트 데이터를 표로 정리해달라는 요청 → 아래 표 참고.

**훈련/검증/테스트 데이터 정리**

| 구분 | 용도 | 학습(파라미터 업데이트)에 사용? | 비유 |
|------|------|-------------------------------------|------|
| **훈련 데이터 (Train)** | 모델의 파라미터(w, b)를 학습 | O | 평소 공부하는 문제집 |
| **검증 데이터 (Validation)** | 어떤 하이퍼파라미터/학습 방법이 가장 좋은지 비교·선택 | X (학습엔 안 쓰지만 모델 선택 과정에는 관여) | 모의고사 |
| **테스트 데이터 (Test)** | 최종 선택된 모델의 성능을 마지막에 **한 번만** 확인 | X | 실제 수능 |

### 교차 검증 (Cross-Validation)

**"어쩌다 한 번 본 모의고사(검증 데이터)를 잘 봤다고 진짜 내 실력이라고 할 수 있을까?"**

- 데이터를 여러 덩어리로 나누어, **여러 번의 모의고사를 체계적으로 치르게** 하여 모델의 성능을 더 안정적이고 신뢰성 있게 평가하는 방법
- 마치 수능 전에 여러 번의 모의고사를 보는 것과 같음

**검증 데이터(단순 분할) vs 교차검증(K-Fold) 비교**

| 구분 | 검증 데이터 (단순 분할) | 교차 검증 (K-Fold) |
|------|--------------------------|----------------------|
| **목적** | 동일 (하이퍼파라미터 튜닝, 중간 성능 측정) | 동일 |
| **'연습 시험지'** | 고정된 1개 | 여러 개(K개)가 돌아가며 역할 수행 |
| **신뢰도** | 데이터 분할에 따라 결과가 좌우될 수 있음 | 더 안정적이고 신뢰도 높은 성능 추정 가능 |
| **비용** | 계산이 빠름 | 모델을 여러 번 학습시켜 시간이 더 걸림 |

**5-Fold 교차검증 절차 (예시)**

1. 전체 데이터(Full Dataset)를 **70% 훈련 데이터 / 30% 테스트 데이터(끝까지 봉인·미접촉, Sealed — untouched)**로 먼저 분리
2. 70% 훈련 데이터를 다시 5개의 폴드(Fold 1~5)로 나눔
3. **Iteration 1~5**: 매 반복마다 폴드 하나가 돌아가며 Validation 역할을 하고, 나머지 4개는 Train 역할 (Iteration 1: Fold1=Validation / Iteration 2: Fold2=Validation / … Iteration 5: Fold5=Validation)
4. 각 Iteration의 검증 점수 예시: 82, 85, 83, 86, 84
5. **평균(Average) = 84 → 이 설정(하이퍼파라미터 조합)을 채택(Select this configuration)**
6. 채택된 설정으로 **테스트 데이터를 단 한 번(Open Test Data Once)** 열어서 → **최종 점수(Final Score)** 확인

> K-fold로 여러 번의 모의고사를 체계적으로 치르게 해서, 모델의 성능을 더 안정적이고 신뢰성 있게 평가하는 방법. 수능 전에 여러 번의 모의고사를 보는 것과 같음.

### [심화 · 참고] ROC Curve

> `[개인 메모 · 시험범위 아님]` 참고 심화 내용 — 정리만 해두고 시험에는 안 나온다고 언급됨.

- **ROC Curve**: 다양한 임계값(threshold) 변화에 따라 성능이 어떻게 달라지는지를 시각적으로 보여주는 그래프
  - 임계값: 분류의 기준. 예를 들어 0.6을 넘으면 Positive, 0.8을 넘으면 Positive로 설정하는 값
- **FPR (False Positive Rate)**: 실제 정상(Negative)인 데이터 중에서 모델이 "암(Positive)"이라고 잘못 예측한 비율. 멀쩡한 사람을 암 환자로 오진할 확률 (0에 가까울수록 좋음)
- **TPR (True Positive Rate)**: 실제 "암"인 데이터 중에서 모델이 "암"이라고 정확히 예측한 비율. 실제 암 환자를 정확히 찾아낼 비율 (1에 가까울수록 좋음)
- **AUC**: ROC Curve 그래프 아래쪽 면적. 1에 가까울수록 성능이 완벽에 가까움, 0.5에 가까울수록 랜덤 추측 수준. 일반적으로 AUC 값이 0.8 이상이면 좋은 모델로 봄

## 5. 비지도 학습 (Unsupervised Learning)

### EDA에서 비지도학습으로 이어지는 흐름

| EDA 도구 | 한계/관찰 | 이어지는 비지도학습 기법 |
|-----------|-----------|----------------------------|
| 히스토그램 | 봉우리가 여러 개면 숨은 하위 그룹이 있다는 신호 | → **K-means (클러스터링)** |
| 페어 플롯 | 변수가 10개만 넘어가도 조합이 너무 많아짐 | → **PCA (차원 축소)** |
| 히트맵 | 상관관계가 0.86처럼 매우 높은 변수쌍 발견 | → **차원 축소의 동기** (중복 정보를 줄이기) |

> `[개인 메모 · 시험범위 아님]` LLM 학습 파이프라인: 사전학습(자기지도) → SFT(지도) → 강화학습(RL) 기준으로, 비지도 → 지도 → 강화 순서의 복합적인 학습으로 결과물을 만들어낸다.

### 차원 축소 (Dimensionality Reduction)

**피처가 많으면 무조건 좋을까?** → 아니다. 성능이 떨어지고 **과적합**이 발생할 수 있음.

> `[개인 메모 · 시험범위 아님]` 차원의 저주(Curse of Dimensionality): 차원이 커지면 점들 간의 유클리디안 거리가 전부 비슷해져서, "가까움/멂"의 의미가 희미해지는 현상.

#### PCA (주성분 분석, Principal Component Analysis)

- 정보 손실을 최소화하면서, 여러 특징을 잘 설명하는 **새로운 핵심 특징 몇 개로 압축**하는 차원 축소 기법

**PCA의 원리 — 럭비공 사진 찍기 비유**

- 럭비공의 특징은 "길쭉한 모양"이 잘 보이도록 사진을 찍는 것이 가장 좋은 사진
- **분산이 가장 큰 방향**으로 축을 잡고, 그 축이 **제1주성분(PC1)**
- 제1주성분과 직각(수직)을 이루는 축이 **제2주성분(PC2)**

> 질문(원문은 괄호 안에 표시됨): 여러 개의 직각 축 후보 중에서, 제2주성분도 그중 "분산이 제일 큰 방향"으로 잡는 게 맞는지?
>
> **답변**: 맞다. 제1주성분과 정확히 직각(orthogonal)을 이루는 방향은 사실 무수히 많다(고차원에서는 그 직각 방향들만 모아도 하나의 초평면을 이룸). PCA는 그 무수히 많은 직각 방향 후보들 중에서도, 데이터가 가장 넓게 퍼져 있는(분산이 가장 큰) 방향을 골라 제2주성분으로 삼는다. 즉 "이전 주성분들과는 모두 직각이면서, 남은 방향들 중 분산이 가장 큰 방향"을 순서대로 계속 찾아나가는 것이 PCA의 원리이며, 이 과정을 반복해서 제3주성분, 제4주성분… 순으로 계속 뽑아낼 수 있다.

### 군집화 (Clustering) — 참고, K-means 복습

- 정답이 없는 데이터들끼리 묶는(클러스터링) 방법
- 사람이 미처 몰랐던 특징이 발견될 수도 있음

**절차 (K-means 복습)**
1. K개의 깃발(중심점)을 아무 데나 꽂음
2. 모든 데이터가 가장 가까운 깃발로 소속됨
3. 각 그룹의 평균 지점에 깃발을 다시 꽂음
4. 중심점이 더 이상 움직이지 않을 때까지 반복

- **K는 하이퍼파라미터** — 사람이 미리 정해줘야 하는 값
- K-means의 난제: **K를 몇 개로 할 것인가?**
- 실무에서는 **실루엣 점수(Silhouette Score)**, **엘보우 기법(Elbow Method)** 등으로 적절한 K를 탐색
